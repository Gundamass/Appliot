# 国内 ATS 回归测试

## 安全边界

- 用户自行选择岗位并完成登录，系统只在进入简历填写页后开始工作。
- 不覆盖页面已有值，不自动勾选法律确认项，不点击任何最终提交控件。
- 测试记录只保留脱敏后的字段类别、选择器特征、数量、错误码和截图。
- 不记录账号、Cookie、令牌、简历原文、联系方式或其他候选人隐私信息。

覆盖内容：

- 只有实习资料时不新增正式工作，实习与项目按档案数量创建。
- 简历上传后重新识别新增的经历区块并继续填写。
- 搜索型专业控件最多尝试两次，并使用候选项点击提交值。
- 年、月独立选择和回读，不把完整年月写入单个控件。
- 获奖语义映射、语言能力填写、用户已有值保留均通过。
- DJI 字段目录、二轮语义补全和待补充追问均可进入正确状态。
- 所有场景的 `submissionCount` 均为 `0`。

## 真实页面检查

每次发布前至少选择一个 DJI/Moka 页面和一个其他国内 ATS 页面执行以下流程：

1. 启动 API、Web、浏览器 Worker 以及当前配置的模型服务，并确认健康检查通过。
2. 创建全新投递任务，由用户在受控浏览器中选择岗位、登录并进入简历填写页。
3. 确认任务阶段从“等待表单”依次进入“确定性填写”“语义补全”“回读校验”“最终审核”。
4. 检查工作与实习分流、专业搜索次数、日期选择结果、重复项目、获奖映射和语言能力。
5. 展开“查看填写明细”，确认失败和未匹配字段有中文原因，且不会计入已填写。
6. 停在最终审核页，确认提交控件仍由用户掌控后结束测试。
