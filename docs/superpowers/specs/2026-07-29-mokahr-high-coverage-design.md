# Mokahr 高覆盖填写设计

## 目标

让受控浏览器在 DJI/Mokahr 投递页先上传用户已确认的 PDF，利用官网解析结果完成基础录入，再完成大部分已确认的简历信息填写，包括动态的教育、项目和实习区块；登录、验证码、岗位选择和最终“预览并提交”仍由用户控制。

## 边界

- 永不自动点击提交、投递、确认申请或语义等价动作。
- 自动化只执行可回读验证的填写、选择、添加条目和安全的下一步/保存操作。
- 页面结构无法可靠识别时，任务暂停并明确交接给用户，不得伪造完成或以普通失败结束。

## 架构

1. 浏览器观察器为每个控件保留稳定 DOM 索引、可见性、可编辑性、标签来源与所在区块。
2. Mokahr 适配器识别上传简历入口、个人信息、教育经历、工作/实习、项目经历等区块，并把“添加”动作与新增字段绑定为一个可验证步骤。
3. 应用服务优先上传 PDF，等待字段结构或值稳定变化；随后按区块对比本地知识库与官网解析结果，执行补空、纠错、添加、重新观察、填写与回读。
4. 发现“预览并提交”时转入审核锁定状态，界面告知用户可在受控浏览器检查并自行点击。
5. 应用编排采用两阶段级联补全：先通过缓存、精确别名和区块规则填写确定字段，再重新观察页面，仅对剩余空字段执行字段注册表语义检索。未知字段不再阻塞同页其他确定字段。
6. 字段语义映射和档案事实查询分离：前者解决“官网字段对应哪个标准路径”，后者只按已确定路径读取已确认值。详细设计见 `2026-07-31-candidate-profile-intelligence-design.md`。

## 验收标准

- 无标签、隐藏、禁用或不可编辑控件不会作为待填写字段。
- 官网支持上传简历时，系统先上传当前任务关联的 PDF，并以页面稳定变化而非固定延时判断解析完成。
- 已被官网正确解析的字段不重复填写；空缺或与已确认资料不一致的字段被补齐或纠正，官网独有信息须交给用户确认。
- DJI/Mokahr 的“预览并提交”归类为终态提交动作，绝不由系统执行。
- 动态“添加”后，新增项目/经历字段被重新观察并按区块填写。
- 每个自动填写字段在快照中可读回预期值；读回失败不计为完成。
- 无安全中间动作时，任务进入人工接管/审核，而非 `failed`。
- 单个未知字段不会阻塞其他确定字段；语义补全仅处理第一阶段后仍为空的字段。
- 中低置信度、敏感承诺和控制页面结构的字段必须在审核区明确标记或保持为空。
