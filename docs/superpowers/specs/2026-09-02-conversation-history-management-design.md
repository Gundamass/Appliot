# 多会话与历史清理设计

日期：2026-09-02  
状态：交互方案已确认，待书面设计审阅

## 1. 背景

当前工作区已经能够将单个对话持久化到 SQLite，并通过 URL 参数和本地最近会话编号恢复页面。对话中的招聘入口搜索、岗位匹配、执行过程和受控投递也已经能够归属到具体会话。

当前缺口是：用户不能查看全部历史会话、不能主动新建或切换会话，也不能删除单条会话或清空全部会话。侧栏因此只能承担页面导航，无法像 Codex 一样成为安静、可扫描的会话入口。

本设计在现有聊天优先工作区中加入完整的会话生命周期管理，同时保持岗位匹配和受控投递的业务边界不变。

## 2. 目标

本期实现：

1. 在统一侧栏中提供新建、展开或收起、切换、删除单条和清空全部会话。
2. 服务端提供会话列表和删除接口，浏览器本地存储只记录最近会话编号，不作为会话事实来源。
3. 新会话默认标题为“新会话”；第一次发送用户消息后，由服务端使用该消息生成标题。
4. 删除当前会话后创建并切换到空白新会话；删除其他会话时保持当前会话不变。
5. 清空全部历史后创建并切换到空白新会话。
6. 三个工作区页面统一使用蓝白侧栏和 Codex 风格的低干扰菜单交互。
7. 删除对话时只删除对话拥有的数据，不删除岗位匹配实体、投递任务、审核记录或候选人资料。

## 3. 非目标

本期不实现：

- 企业招聘网站中的后续状态查询、同步或跟踪。
- 会话重命名、置顶、搜索、分组、归档、导出或回收站。
- 跨设备、跨账号同步及多用户权限模型。
- 自动删除长期未使用会话。
- 修改岗位推荐、岗位选择、受控填写、登录或验证码人工接管、字段回读、风险控制和最终提交硬锁逻辑。

## 4. 既有约束

- `conversation_sessions` 已是消息、上下文、幂等轮次、确认记录和执行过程的父实体。
- `conversation_job_match_sessions` 只保存对话与岗位匹配的关联。删除关联不会删除 `job_match_sessions` 本身。
- 投递任务、审核记录和候选人资料不以会话为父实体，不能纳入会话删除事务。
- 当前岗位匹配深链接会尝试找到归属会话；归属会话已删除时，沿用现有恢复提示并返回最近会话或新会话，不伪造新的归属关系。
- 一个会话同一时间只允许一个发送或确认动作。会话正在处理请求时，当前会话删除和清空全部会话暂不可用。

## 5. 用户界面

### 5.1 统一侧栏结构

侧栏从上到下为：

```text
对话首页                                      ···
  新建会话
  当前会话标题                                ···
  其他会话标题                                ···
投递进度
我的简历
```

`对话首页` 是可展开的一级入口。点击标题区域进入当前对话并展开或收起会话列表；右侧三个点是独立的更多操作按钮。`投递进度` 和 `我的简历` 保留为一级页面入口。

三个页面始终使用同一个 `WorkspaceFrame`，因此侧栏结构、颜色、间距、选中状态和会话列表不会因切换页面而变化。

### 5.2 Codex 风格交互

- `对话首页` 标题和三个点属于同一行悬停区域。浅蓝背景覆盖整行，包括三个点右侧；悬停、键盘聚焦或菜单展开时整行背景加深。
- 顶层三个点保持低对比度，悬停、聚焦或展开菜单时提高对比度。
- 会话项默认不显示危险操作。当前会话、鼠标悬停项或键盘聚焦项显示低干扰三个点。
- 会话项的三个点打开上下文菜单，菜单内只显示红色“删除会话”。红色不出现在普通会话行中。
- 顶层三个点打开菜单，菜单内显示红色“清空历史会话”。
- 点击菜单外、按 `Escape` 或完成操作后关闭菜单。菜单按钮使用 `aria-haspopup="menu"` 和 `aria-expanded`，菜单项可通过键盘操作。

### 5.3 会话项

每项显示：

- 最多两行的会话标题，超出可见宽度时省略。
- “刚刚”“昨天”或本地化日期形式的最近更新时间。
- 当前项的浅蓝选中背景。

会话按 `updatedAt` 降序排列。当前会话完成一次成功发送后，更新时间和标题立即更新，并移动到列表首位。失败的发送不改变标题。

### 5.4 新建与切换

点击“新建会话”后：

1. 调用服务端创建会话。
2. 将返回的会话插入列表首位。
3. 切换到对话首页，将 URL 更新为 `/?conversation=<id>`。
4. 显示空白对话和快速开始入口，输入框获得焦点。

点击历史会话后，先更新当前会话编号和 URL，再由聊天区域加载该会话的消息、上下文、待确认项和执行过程。切换会话会断开旧会话 SSE，并连接新会话 SSE；两个会话的本地展示状态不混用。

### 5.5 删除单条会话

点击“删除会话”先展示确认对话框：

> 会话消息和执行过程将被删除，岗位匹配和投递任务会保留。此操作无法撤销。

确认后：

- 删除其他会话：从列表移除该项，当前页面和 URL 保持不变。
- 删除当前会话：服务端删除成功后立即创建一个空白会话，切换到该会话并替换 URL。
- 删除请求失败：保留原列表和当前会话，显示可重试错误，不进行乐观删除。

当前会话正在发送、确认或执行岗位匹配动作时，其删除菜单项为禁用状态；其他非当前会话仍可删除。

### 5.6 清空全部会话

点击“清空历史会话”先展示确认对话框：

> 全部对话消息和执行过程将被删除，岗位匹配和投递任务会保留。此操作无法撤销。

确认后，客户端调用服务端清空接口；成功后创建一个空白会话并替换当前 URL。清空失败时保留全部现有数据和列表，不创建新会话。

当前会话正在处理请求时，“清空历史会话”禁用，避免删除仍在写入的会话。

### 5.7 窄屏行为

- 窄屏保留三个一级入口，不将会话列表横向铺开。
- 点击“对话首页”时在导航下方展开会话列表；选择会话后自动收起列表并进入聊天。
- 三个点和菜单项保持至少约 44px 的触控区域。
- 弹出菜单和确认对话框不能超出视口或遮挡确认按钮。

## 6. 合约与 API

### 6.1 会话摘要

列表直接复用 `ConversationSession` 作为摘要：

```ts
type ConversationSession = {
  id: string;
  title: string;
  createdAt: string;
  updatedAt: string;
};
```

不在列表接口中返回消息、上下文、岗位卡片或执行过程，避免随着历史增长放大首页请求。

### 6.2 新增接口

```text
GET    /api/conversations       -> ConversationSession[]
DELETE /api/conversations/:id   -> 204 No Content
DELETE /api/conversations       -> { deletedCount: number }
```

现有接口保持不变：

```text
POST /api/conversations
GET  /api/conversations/:id
POST /api/conversations/:id/messages
POST /api/conversations/:id/confirm
GET  /api/conversations/:id/events
```

行为约定：

- 列表按 `updated_at DESC, created_at DESC, id DESC` 返回，保证相同时间戳下顺序稳定。
- 单条删除不存在的会话返回 `404 conversation_not_found`。
- 清空全部是幂等操作；没有会话时返回 `{ deletedCount: 0 }`。
- 删除接口不接受岗位匹配编号或投递任务编号。
- 所有响应继续通过共享 Zod 合约校验；错误消息保持长度受限，不暴露 SQL 或内部堆栈。

## 7. 标题生成

### 7.1 规则

- 新建标题固定为“新会话”。
- 仅第一次成功写入用户消息时生成标题。
- 标题来源是该用户消息：去除首尾空白，将连续空白折叠为一个空格，再取前 20 个 Unicode 字符。
- 不追加省略号；生成结果至少包含一个字符。
- 后续消息不再自动改名。
- 服务端生成并持久化标题，前端不能自行推测最终标题。

### 7.2 原子性

标题更新与首次对话轮次写入位于同一个数据库事务中。只有会话标题仍是默认标题、且事务成功写入首条用户消息时才更新。幂等重试命中已有轮次时，不重复生成标题或更新时间。

### 7.3 旧数据

数据库升级时仅处理仍为旧占位标题 `New conversation` 的会话：

- 有用户消息：按同一规则从第一条用户消息回填标题。
- 没有用户消息：改为“新会话”。
- 已有自定义或历史生成标题保持不变。

## 8. 服务端设计

### 8.1 Repository

`ConversationRepository` 增加：

```ts
listConversations(): ConversationSession[];
deleteConversation(id: string): boolean;
deleteAllConversations(): number;
```

首次标题生成放入现有 `appendTurn` 事务，不提供可由外部任意改名的通用接口。

### 8.2 删除边界

删除 `conversation_sessions` 后由外键级联删除：

- `conversation_messages`
- `conversation_contexts`
- `conversation_turns`
- `conversation_confirmations`
- `conversation_process_events`
- `conversation_process_event_cursors`
- `conversation_job_match_sessions` 关联行

明确保留：

- `job_match_sessions` 及其岗位、匹配结果和游标
- `application_tasks` 及其受控填写和人工接管状态
- 自我评价等审核记录
- 候选人资料、简历文档、证据和向量索引
- 提交锁、风险控制和浏览器任务安全约束

Repository 测试必须证明删除关联行后岗位匹配实体仍存在。清空全部使用单个数据库事务，不能逐条调用 HTTP 或产生部分删除。

### 8.3 执行过程清理

数据库中的执行过程由外键级联清理。事件总线同步提供会话级清理方法，删除成功后移除对应的内存回放缓冲和裁剪游标，避免本地服务长期运行时保留已删除会话事件。

当前页面在执行删除前已禁止仍在运行的当前会话操作；如果其他标签页删除了正在查看的会话，后续消息或确认请求会收到 `conversation_not_found`，客户端按失效会话恢复流程处理。

### 8.4 路由与服务

- 路由只负责参数校验、状态码和受限错误映射。
- 会话列表和删除由会话服务协调 Repository 与执行事件总线。
- 删除岗位匹配归属关联是外键级联结果，不主动调用岗位匹配删除方法。
- 清空接口返回事务实际删除的会话数量。

## 9. 前端架构

### 9.1 工作区控制器

`ProfileApplicationWorkspace` 成为会话生命周期的唯一控制器，负责：

- 加载会话列表。
- 根据 URL、本地最近会话和列表选择当前会话。
- 创建、切换、删除和清空会话。
- 同步 `conversation` URL 参数和最近会话本地记录。
- 将会话导航模型传给统一 `WorkspaceFrame`。
- 接收 `ChatHome` 的忙碌状态，在当前请求执行期间禁用当前会话删除和清空操作。

首次进入的选择顺序：

1. URL 中存在且服务端列表中存在的会话。
2. 本地最近会话编号存在且服务端列表中存在的会话。
3. 服务端列表中的最新会话。
4. 列表为空时创建空白会话。

失效的 URL 或本地编号会被替换，不反复请求已删除会话。

### 9.2 WorkspaceFrame

`WorkspaceFrame` 继续是展示组件，新增会话导航所需属性和回调，不直接调用 API。它负责：

- 统一渲染三个一级入口。
- 渲染展开的会话列表、加载态、空态和错误态。
- 管理菜单开关、键盘关闭和删除确认对话框。
- 将新建、切换、删除、清空意图回传给工作区控制器。

菜单打开状态只属于界面，不写入 URL 或本地存储。

`ProfileApplicationWorkspace` 不再为聊天页提前返回，而是始终在三个页面外层渲染一次 `WorkspaceFrame`。`ChatHome` 移除内部的 `WorkspaceFrame`，从而避免聊天页与其他页面形成两套导航所有权。

### 9.3 ChatHome

`ChatHome` 改为接收已确定的 `conversationId`，不再自行决定是否创建会话。会话编号变化时：

- 清空上一会话的临时消息、错误、待确认项和执行事件。
- 加载新会话详情。
- 重新建立该会话的 SSE 连接。
- 忽略旧请求晚到的响应，防止跨会话污染。

`ChatHome` 通过 `onBusyChange` 报告发送、确认和岗位匹配动作的忙碌状态；通过 `onConversationUpdated` 报告一次成功的会话写入。工作区控制器收到更新后重新请求会话列表，以获得服务端生成的标题和权威 `updatedAt`，不在浏览器中单独截取或推测标题。

### 9.4 ConversationApi

前端 `ConversationApi` 增加：

```ts
list(): Promise<ConversationSession[]>;
delete(id: string): Promise<void>;
deleteAll(): Promise<{ deletedCount: number }>;
```

所有返回继续经共享合约解析。网络错误、非法响应和服务端错误使用现有 `ConversationApiError` 映射。

## 10. 状态与异常处理

### 10.1 加载失败

- 会话列表失败：显示侧栏内联错误和重试入口；已有当前会话可继续显示时不清空聊天。
- 当前会话详情失败且为 404：从列表移除失效项，按首次进入选择顺序恢复。
- 当前会话详情为其他错误：保留当前编号并显示重试，不静默创建重复会话。

### 10.2 创建失败

新建失败时保留原会话和 URL，按钮恢复可用并显示错误。删除当前会话或清空全部之后创建替代会话失败时，进入明确的空状态，提供“重新创建会话”操作；下次刷新也会因列表为空自动创建。

### 10.3 删除并发

- 删除按钮提交后禁用，防止重复请求。
- 其他标签页已经删除同一会话导致 404 时，客户端刷新列表并按失效会话恢复处理。
- 清空全部重复执行视为成功，不把 `deletedCount: 0` 显示为错误。
- 正在发送的当前会话不允许由同一页面删除或清空；服务端仍以外键和 404 处理跨标签页竞争。

### 10.4 本地存储

本地存储只保存最近会话编号。删除当前或清空全部后立即移除旧编号，替代会话创建成功后写入新编号。本地存储不可用时 URL 和服务端列表仍能完成全部功能。

## 11. 测试策略

### 11.1 合约测试

- 会话列表和清空结果接受合法结构，拒绝超长标题、非法时间和额外字段。
- 标题生成覆盖中文、英文、Emoji、连续空白和超过 20 个字符的输入。

### 11.2 Repository 与迁移测试

- 列表顺序稳定，发送成功后更新时间改变并移到首位。
- 首条用户消息原子生成标题，后续消息和幂等重试不改标题。
- 旧占位标题按规则回填。
- 单条删除级联清理全部对话子表。
- 单条删除保留岗位匹配实体、投递任务、审核记录和候选人资料。
- 清空全部返回正确数量且事务完整。
- 事件总线删除内存回放数据。

### 11.3 路由与 API 客户端测试

- `GET /api/conversations` 返回稳定排序列表。
- 单条删除的 204、404 和参数校验正确。
- 清空全部成功、重复清空和内部失败映射正确。
- 前端 API 使用正确方法和编码后的路径，并拒绝非法响应。

### 11.4 组件测试

- 三个页面共享相同侧栏结构和选中风格。
- 对话列表展开或收起、新建、切换和时间标签正确。
- 顶层整行悬停背景覆盖到三个点；三个点悬停和菜单展开状态可辨识。
- 非当前会话的三个点默认隐藏，悬停、聚焦和触控场景可访问。
- 红色删除动作只出现在菜单和确认对话框。
- 删除当前、删除其他和清空全部分别触发正确回调和确认文案。
- 菜单外点击、`Escape`、焦点移动和窄屏布局正确。

### 11.5 集成与回归测试

- URL、本地最近编号、服务端列表和空列表四种启动路径。
- 连续切换会话时旧详情和旧 SSE 事件不会进入新会话。
- 删除当前后创建空白会话；删除其他时当前会话不变；清空后只剩替代会话。
- 刷新页面后会话标题、顺序、消息、岗位卡片和执行过程恢复正确。
- 现有招聘入口搜索、两次确认、岗位匹配、岗位选择和投递卡片流程继续通过。
- 现有受控填写、登录或验证码人工接管、字段回读、风险控制和最终提交硬锁测试继续通过。
- 不新增企业招聘状态跟踪接口、表或界面。

## 12. 验收标准

1. 用户可以在侧栏新建、切换、删除单条和清空全部会话。
2. 会话列表来自服务端，刷新和重启后仍存在，本地存储不是事实来源。
3. 新会话显示“新会话”，第一次成功发送后标题变为规范化消息的前 20 个 Unicode 字符。
4. 删除当前会话后进入空白新会话；删除其他会话不改变当前页面。
5. 清空全部会话后进入空白新会话。
