# 跨 ATS 稳定化设计

## 目标

在保持“绝不自动提交”的前提下，优先提高国内 ATS 的自动填写覆盖率，同时兼容 Greenhouse、Lever、Workday、Ashby 及后续未知招聘网站，使用户主要参与最终审核，而不是在填写过程中反复补充已有档案信息。

本轮聚焦真实回归中暴露的六类问题：搜索型超大下拉框、复杂控件漏识别、动态页面过早观察、英文语义映射不足、非必填字段过度追问，以及文件上传控件标签污染。

## 适配优先级

开发和回归按以下顺序进行：

1. 国内 ATS 第一优先：先保证现有 Moka/DJI 主流程不回归，再覆盖国内页面常见的院校/专业/地区搜索下拉、年月日拆分控件、级联选择器、重复教育/实习/项目经历和中文必填提示。
2. 国内其他 ATS 第二优先：使用北森、网申类系统的公开页面或等价结构夹具验证通用能力；不为单一站点复制完整流程。
3. 海外 ATS 兼容回归：Greenhouse、Lever、Workday、Ashby 用于验证英文语义、搜索型超大下拉、动态登录页和复杂 ARIA 控件。

实现顺序只改变验收优先级，不改变通用控件模型。国内 ATS 出现的新控件模式应沉淀为通用能力，站点规则仅保留页面阶段和局部结构差异。

## 总体方案

采用“通用控件引擎 + 少量 ATS 兼容规则”。通用引擎负责发现、建模、填写和回读验证；ATS 规则只描述页面阶段、稳定条件和无法通过通用可访问性语义恢复的局部结构，不为每个网站复制完整填写流程。

填写分为两轮：

1. 使用确定性别名和明确的 `semanticHint` 填写高置信字段。
2. 重新观察页面，仅对仍为空的必填字段和已有档案证据的字段执行受阈值限制的语义检索。

两轮之后进入最终审核。任何字段回读不一致都标记为审核风险，不触发最终提交。

## 控件观察模型

观察器需要把以下交互统一建模为字段，而不是普通页面动作：

- 原生 `input`、`textarea`、`select`。
- `role=combobox` 及常见自定义搜索选择器。
- 由一组按钮表达的单选问题，例如 Yes/No。
- 原生或 ARIA 单选组、复选框。
- 日期输入框和由多个年月日控件组成的日期组。
- 隐藏文件输入框及其可见上传包装器。

字段标签按可访问性信息优先恢复：显式 `label`、`aria-labelledby`、`aria-label`、问题容器标题、相邻问题文本、占位符、`name`。按钮组和单选组共享上层问题标签，每个选项只作为 `options`，不能成为独立的中间操作。

文件字段只保留问题标题，例如“Resume”，不得拼接上传提示、解析状态和按钮文案。重复指向同一文件输入框的可见包装器需要去重。

## 搜索型下拉框

搜索型或虚拟化下拉框不预取全部候选项，也不把数千项写入任务响应。其快照只包含当前值、可访问标签和少量当前可见候选项。

执行流程：

1. 聚焦控件并输入档案候选值，例如学校全称。
2. 等待候选列表根据输入稳定更新。
3. 优先选择规范化后完全相等的候选项。
4. 无完全匹配时，仅允许已有语义策略判定为高置信的唯一候选项。
5. 候选不唯一或低于阈值时保留为空并进入最终审核，不枚举全量选项。
6. 选择后重新观察并回读显示值，只有回读匹配才记为填写成功。

任务响应中的普通选项仍设置防御性上限。超过上限时截断可见候选并记录诊断信息，不得因为 Schema 校验导致整个任务创建失败。

## 页面阶段与等待

页面观察不再只等待表单字段。职位页、登录页和申请页都等待以下任一有效信号出现并短暂稳定：

- 可填写字段。
- 登录或登录方式选择动作。
- Apply、Continue、Next 等安全中间动作。
- 明确的页面错误。

Workday 等动态职位页在路由不含 `/apply` 时也必须等待申请动作加载。只有按钮式登录入口的页面应识别为 `login`，并进入 `waiting_for_login`；空字段快照不得直接进入验证阶段。

等待使用条件轮询和总超时，不依赖单个固定延时。超时结果必须指出“未观察到字段或可继续动作”，不能统一误报为受控浏览器不可用。

## 语义映射与检索

确定性映射补充常见中英文别名：

- 姓名：Legal Name、Full Name、First/Given Name、Last/Family Name。
- 联系方式：Phone Number、Mobile、Email Address。
- 地点：Current Location、Current Address、Where are you currently located。
- 入职信息：Earliest Start Date、Availability、When can you start。
- 搬迁和工作授权：Relocation、Authorized to Work、Visa Sponsorship。

拆分姓名只允许使用用户明确保存的中文姓名、英文姓名或结构化姓名字段，不由模型猜测姓名顺序。

第二轮语义检索只处理仍为空且具备候选档案事实的字段。重复区块先由确定性规则建立索引上下文，例如“赛事名称”“赛事时间 年/月”先归入 `awards[0]`，再由语义检索落到 `awards[0].name` 或 `awards[0].date`。检索结果必须经过字段类型、实体范围、选项兼容性和相似度阈值验证；未通过验证的候选不能填写。

字段执行返回非终态失败时，应用服务最多执行一次受控恢复：失效旧执行令牌、重新观察页面，确认 URL、阶段和字段结构未变化且目标仍为空，再调用一次语义解析并重试 `fill/select`。上传、页面导航和任何提交动作不进入该自动重试；恢复仍失败则记录字段失败并交给用户审核。

## 追问与敏感信息规则

- 必填字段缺少资料时才产生任务内追问。
- 非必填字段缺少资料时静默跳过，不中断流程。
- 非必填字段若档案已有高置信资料，可以自动填写并回读验证。
- 性别、种族、残障、退伍状态等敏感信息只使用用户在档案中明确保存的答案，禁止从姓名、经历或其他事实推断。
- 敏感字段没有显式答案时保持为空；非必填不追问，必填进入最终审核。
- 法律协议、真实性声明和其他具有证明意义的确认框永不自动勾选，集中显示在最终审核中由用户亲自确认。

## 安全与错误处理

- `Submit Application`、提交表单请求和等价终端动作继续由现有策略层阻断。
- 自动操作只允许填写、选择、上传和客观安全的中间导航。
- 每次操作都必须重新观察和回读；失败不能伪装为成功。稳定页面上的字段失败只允许一次语义恢复，页面漂移或恢复失败必须暂停。
- 单个字段观察或映射失败不得使整个任务创建失败。
- API 返回结构化错误码，区分浏览器不可用、页面等待超时、字段不支持、选项过多和回读不一致。

## 测试策略

所有行为按测试先行实现：

1. Observer 单元测试覆盖 Ashby 风格按钮组、ARIA 单选/复选、自定义地点控件、日期问题标签和上传包装器去重。
2. Executor 测试覆盖搜索后选择、候选不唯一、结果回读和超大选项截断。
3. Application Service 与 RAG 测试覆盖英文别名、两轮填充、非必填静默跳过和敏感信息规则。
4. 状态机测试覆盖 Workday 动态职位页、登录方式选择页和观察超时错误。
5. 浏览器回归先扩充 DJI/Moka，并增加国内 ATS 常见结构夹具；随后增加 Greenhouse、Lever、Workday、Ashby 结构化夹具。
6. 最后按“国内 ATS 在前、海外 ATS 在后”的顺序使用真实公开页面执行隔离回归，使用合成档案，确认不触发最终提交。

## 验收标准

- Lever 超大院校下拉不再导致任务创建失败，并能通过输入学校名筛选后选择。
- DJI/Moka 现有姓名、联系方式、教育、实习、项目和拆分日期填写不得回归；国内常见院校、专业和地区搜索控件能先输入再选择。
- Workday 动态职位页能等待 Apply 出现，登录方式页进入等待用户登录状态。
- Ashby 的姓名、电话、地点、日期、按钮式 Yes/No、单选和复选控件能够被正确建模。
- Greenhouse 常见英文姓名、联系方式、地点、入职日期和搬迁字段能映射已有档案。
- 非必填缺失字段不生成追问；敏感信息不被推断；法律确认框不被自动勾选。
- 所有自动填写结果都有回读证据，任何真实回归均不点击或请求最终提交。
