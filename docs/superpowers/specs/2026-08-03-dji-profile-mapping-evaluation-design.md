# 大疆候选人档案字段覆盖与映射评测设计

## 1. 背景

当前系统已经具备候选人档案、PDF 简历导入、RAG 检索和受控浏览器填写能力，但真实招聘页面的字段比一页 PDF 简历丰富得多。现有问题集中在两个方面：档案字段覆盖不足，以及页面字段没有被统一评测和解释。

本阶段以大疆招聘页面为第一个完整适配目标，同时保留通用字段映射接口，为后续接入其他招聘网站做准备。

## 2. 目标

1. 建立大疆申请页面的字段目录，覆盖字段类型、选项、校验规则和语义标签。
2. 在投递任务开始前评估候选人档案对页面字段的覆盖程度。
3. 按“精确匹配 -> 别名和枚举转换 -> 语义检索 -> 验证”的顺序生成映射决策。
4. 让每个填写结果都能追溯到档案字段、原文证据或用户修正。
5. 低置信度字段不得自动填写，必须进入审核或追问流程。
6. 用户确认的修正可以选择保存为长期档案，也可以仅用于本次投递。
7. 任何流程都只能停留在审核锁，禁止执行招聘网站最终提交。

## 3. 非目标

- 本阶段不同时开发多个招聘网站适配器。
- 不自动生成项目描述、实习描述或项目亮点。
- 不将用户未确认的任务内容写入长期档案。
- 不通过 Agent 取代确定性的页面观察、字段校验和提交拦截代码。

## 4. 方案比较

### 方案 A：纯配置映射

通过配置表把招聘页面字段直接映射到档案路径。实现最快，但对同义字段、动态字段和选项差异的适应性较弱。

### 方案 B：混合映射矩阵（采用）

先执行确定性映射，再对剩余字段执行受约束的语义检索，并将结果交给验证器。它兼顾稳定性、可解释性和多站点扩展能力，且可以控制模型调用次数。

### 方案 C：全 Agent 自主填写

由 Agent 规划并决定所有字段操作。灵活性最高，但成本、时序稳定性和错误解释能力较差，不适合作为当前主链路。

## 5. 系统设计

### 5.1 大疆字段目录

新增站点适配层，记录每个页面字段的：

- 稳定字段标识和页面标签
- 字段类型：文本、长文本、日期、下拉框、复选框、上传等
- 所属栏目和重复记录类型
- 允许的选项及标准化值
- 必填规则、格式校验和敏感级别
- 通用语义标签，例如 `education[0].institution`、`work[0].position`

目录只描述页面，不保存候选人的具体答案。页面发生变化时，适配层可以独立更新。

### 5.2 映射决策链

对每一个空字段按以下顺序处理：

1. **精确匹配**：稳定语义路径或已确认的站点映射。
2. **别名匹配**：中文、英文、常见缩写和字段名称归一化。
3. **枚举转换**：把档案值转换成页面实际选项，转换后必须通过选项校验。
4. **语义检索**：仅在前面没有结果时检索档案事实和证据。
5. **验证**：检查类型、格式、必填、选项、来源和敏感级别。

决策结果至少包含：页面字段、候选值、来源档案路径、证据、匹配方式、置信度、验证结果和下一步动作。

### 5.3 置信度策略

阈值由配置管理，不散落在页面代码中。初始策略如下：

- 精确匹配且通过验证：允许自动填写。
- 语义匹配置信度不低于 `0.90` 且证据唯一、验证通过：允许自动填写。
- `0.75` 至 `0.90`：不自动填写，进入人工审核。
- 低于 `0.75`、证据冲突或没有证据：进入追问或标记为未匹配。
- 下拉选项、布尔值和敏感字段需要更严格验证；不能唯一确定时不得自动填写。
- 自我评价可以基于岗位做微调，但必须展示原文、调整稿、调整理由和证据，用户确认后才可填写。
- 项目描述、实习描述和项目亮点保持用户原文，不由系统生成或静默改写。

### 5.4 覆盖评测

投递任务观察到页面结构后，先生成一份字段覆盖报告：

- 可直接填写
- 语义匹配待确认
- 档案缺失
- 页面字段未知
- 页面字段不支持安全自动填写

报告只针对当前任务，不修改长期档案。用户补充资料后，系统只重新评估受影响字段，避免重复调用模型。

### 5.5 审核工作区

字段审核整合到投递任务工作台，不再依赖独立的 RAG 演示页。每个待审核字段显示：

- 页面原文和字段位置
- 系统建议值
- 系统理解的语义
- 匹配方式和置信度
- 档案来源与 PDF 页码/证据
- 接受、编辑、跳过和追问操作

审核完成后才允许继续自动填写；最终按钮仍然是审核锁，不提供提交动作。

## 6. 数据流

1. 受控浏览器观察大疆页面并生成结构化字段快照。
2. DJI 字段目录为快照字段补充类型、选项和语义提示。
3. 映射器先读取档案事实，再按需要调用关键词或向量检索。
4. 验证器输出字段决策和证据链。
5. 任务工作台展示覆盖报告和待审核项。
6. 用户确认或修正后，系统执行安全填写并进行页面回读验证。
7. 页面进入审核锁，系统记录未提交状态。

## 7. 错误与安全边界

- 页面结构变化时，暂停任务并展示受影响字段，不盲填。
- 选项无法对应时，不用最相近文本强行填写。
- 模型、向量服务或 OCR 离线时，精确匹配仍可继续，语义字段进入待审核。
- 每次自动填写后都必须回读页面值；回读失败时重试一次，仍失败则暂停。
- 用户手动操作页面时，立即停止当前自动操作并重新观察。
- 任何提交、发送、确认投递或同义按钮都由策略层永久拦截。

## 8. 测试与验收

### 单元测试

- DJI 字段目录能正确归一化字段类型、选项和重复记录。
- 精确、别名、枚举和语义映射按优先级执行。
- 各置信度区间产生正确动作。
- 证据缺失、证据冲突和低置信度不会自动填写。
- 用户修正可以区分“仅本次任务”和“保存到长期档案”。

### 集成测试

- 真实页面快照可以生成覆盖报告。
- 档案补全后只重新评估受影响字段。
- 自动填写后页面回读值与决策值一致。
- 页面变化、登录、用户接管和服务离线都能进入可恢复状态。

### 端到端验收

使用大疆测试链接完成岗位选择、登录、资料填写和审核锁流程，断言：

- 主要教育、实习、项目、获奖和联系方式字段能够得到明确决策。
- 无证据或低置信度字段不会被静默填写。
- 用户可查看并修正建议值。
- 网络、模型和浏览器异常不会导致任务永久卡死。
- `submissionCount` 始终为 `0`。

## 9. 分阶段交付

1. 建立 DJI 字段目录和通用字段决策模型。
2. 将覆盖评测接入任务创建和任务工作台。
3. 接入证据展示、用户修正和档案回写选择。
4. 补齐大疆真实页面回归测试并完成审核锁验收。
