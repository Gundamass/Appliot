# 岗位推荐百分比与前六结果设计

## 目标

岗位推荐结果只向用户展示匹配度百分比，并且只保留现有排序规则下最符合的前六条推荐。

## 设计

- 继续使用现有 `fitScore` 作为匹配度来源。它已经由评分器限制在 0 到 100 之间，因此页面显示为 `匹配度 X%`，不新增换算或新的评分算法。
- 保留 `confidence`、`rankingScore` 和内部 `score` 字段用于排序、审计、接口兼容及后续投递校验，但不在推荐卡片上展示“分数”或“置信度”。
- 在岗位匹配子图完成既有排序后，将无明确冲突的推荐 ID 截取前六条；冲突判断和内部完整结果仍保留，避免破坏冲突确认、结果校验及审计链路。
- API 展示层按相同的推荐排序再次限制为六条，前端 `ConversationJobCards` 也做六条兜底，确保旧会话或异常接口数据不会在页面显示超过六条。
- 旧的对话推荐卡片同样将内部 `score` 显示为 `匹配度 X%`，并限制列表工具生成的卡片数量为六条。

## 验证

- API 子图测试验证超过六条候选时推荐 ID 只返回六条。
- API 服务测试验证对外展示结果最多六条。
- Web 组件测试验证最多渲染六张岗位卡片，显示百分比且不显示“分”或“置信度”。
- 运行相关包测试、类型检查和前后端联调回归。
