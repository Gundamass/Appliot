# 岗位推荐确认文案与浏览器租约修复设计

## 背景

快速开始流程中，用户选择百度招聘入口并点击“开始岗位推荐”后，消息被错误记录为“确认开始投递”，随后岗位推荐可能显示通用失败提示。

真实会话跟踪表明，这两个现象来自不同问题：

- 前端和 API 将所有确认动作统一硬编码为“确认开始投递”。
- 已完成岗位匹配的会话进入 `awaiting_job_selection` 后仍持有受控浏览器租约，后续岗位推荐在打开招聘页面前即以 `browser_lease_in_use` 失败。
- 对话错误映射没有覆盖 `browser_lease_in_use`，因此用户只能看到无法定位原因的通用提示。

百度招聘根地址由岗位匹配服务转换为岗位列表地址后再交给受控浏览器。本次失败发生在浏览器租约获取阶段，不是百度页面识别阶段。

## 目标

1. 确认消息准确反映当前动作。
2. 岗位推荐结果生成后不再无期限占用受控浏览器。
3. 浏览器确实被占用时显示明确、可操作的提示。
4. 保持百度官方招聘根地址到岗位列表地址的转换行为，并通过回归测试保护该行为。

## 非目标

- 不引入多浏览器并发池。
- 不自动取消或删除旧岗位匹配会话。
- 不改变岗位评分、推荐数量或投递审批策略。
- 不在本次修复中重构招聘入口搜索排序。

## 设计

### 1. 按确认动作生成消息文案

前端乐观消息和 API 持久化消息使用相同的动作映射：

| 确认动作 | 同意文案 | 拒绝文案 |
| --- | --- | --- |
| `confirm_recruitment_site` | 确认使用此入口 | 暂不使用此入口 |
| `request_job_recommendations` | 开始岗位推荐 | 暂不推荐 |
| `start_application` | 确认开始投递 | 取消开始投递 |

前端根据当前 `pendingConfirmation.action` 生成乐观消息；API 根据服务端保存的待确认动作生成最终持久化消息。服务端仍是最终事实来源，刷新后消息必须与持久化结果一致。

### 2. 在岗位推荐完成后释放浏览器

岗位列表读取、筛选和匹配完成后，会话进入 `awaiting_job_selection`。此时选择岗位只依赖已持久化的岗位与匹配结果，不需要继续保持招聘页面所有权。

因此在状态成功转换为 `awaiting_job_selection` 后：

1. 释放 `BrowserOwnershipLease` 中属于该岗位匹配会话的所有权。
2. 调用浏览器端 `releaseTask` 清理该会话的页面绑定。
3. 保留岗位匹配会话、岗位数据和推荐结果，用户仍可正常查看和选择。

`awaiting_filter_confirmation`、`awaiting_login` 和 `awaiting_challenge` 等仍需继续操作当前页面的状态不提前释放租约。现有暂停、取消和转换投递流程的释放行为保持不变。

### 3. 明确显示浏览器占用错误

对话错误映射新增以下兼容处理：

- `browser_lease_in_use`
- `browser_task_in_use`

统一提示为：

> 受控浏览器正在处理其他岗位匹配或投递任务，请等待当前任务完成或先暂停它后再试。

错误码继续记录在审计跟踪中，不再降级为“这项操作暂时无法完成”。

### 4. 百度入口处理

已确认的 `https://talent.baidu.com/` 仍由百度适配器转换为校园招聘岗位列表地址，再执行页面识别。招聘入口卡片可以继续展示官方根地址；岗位匹配使用内部标准化地址。

本次回归需验证：

- 根地址会在调用浏览器前转换成岗位列表地址。
- 浏览器租约可用时，失败不会发生在租约获取阶段。
- 如果百度页面结构变化，用户收到“当前招聘页面结构尚未识别”的专用提示，而不是浏览器占用或通用错误。

## 测试策略

采用测试驱动开发，每个行为先增加失败测试：

1. Web 组件测试：岗位推荐确认显示“开始岗位推荐”，入口确认显示“确认使用此入口”。
2. 对话服务测试：持久化的用户确认消息与待确认动作一致。
3. 岗位匹配服务测试：完成匹配进入 `awaiting_job_selection` 后，租约为空且 `releaseTask` 被调用。
4. 顺序会话测试：第一个岗位匹配完成后，第二个岗位匹配可以取得租约。
5. 对话图测试：`browser_lease_in_use` 映射为明确提示。
6. 百度适配器及服务测试：官方根地址继续标准化为受支持的岗位列表地址。
7. 前后端联调回归：依次运行大疆和百度岗位推荐，确认第二个任务不再因旧租约失败；不执行真实岗位投递。

## 验收标准

- 点击“开始岗位推荐”后，用户消息显示“开始岗位推荐”。
- 点击招聘入口确认后，用户消息显示“确认使用此入口”。
- 一个岗位推荐进入待选择状态后，可以立即启动另一家公司的岗位推荐。
- 浏览器确实忙碌时，界面显示专用提示并保留原始审计错误码。
- 百度根地址在后台打开前被转换为岗位列表地址。
- 相关单元测试、集成测试和前端浏览器回归全部通过。

## 风险与控制

- 过早释放浏览器可能影响登录或验证码恢复。通过仅在 `awaiting_job_selection` 成功状态释放来避免。
- 前后端文案映射可能漂移。两层分别测试同一动作矩阵，并以后端持久化消息作为刷新后的最终结果。
- 百度网站可能继续调整页面结构。标准化和页面识别测试分开，确保错误能准确归因。
