# 岗位匹配创建入口设计

## 背景

岗位匹配后端已经提供 `POST /api/job-match-sessions`，Web 端也已经具备 `JobMatchApi.create()`、会话工作台和 `/job-match-sessions/:sessionId` 路由。但是主工作区只接入了直接投递流程，没有任何生产界面调用会话创建 API。用户因此无法从主界面输入招聘链接并进入岗位匹配流程。

本增量补齐创建入口，同时保持 `JobMatchSession` 与 `ApplicationTask` 分离。用户确认岗位之前不得创建投递任务，任何入口行为都不得触发 ATS 最终提交。

## 目标

- 在现有“新建投递”视图提供默认的岗位匹配入口。
- 让用户在打开招聘网站前核对知识库中的岗位期望。
- 将核对结果写回知识库，并以知识库快照创建匹配会话。
- 对岗位列表、岗位详情和投递表单三种入口给出明确分流。
- 保留现有直接投递能力和安全边界。

## 非目标

- 不新增独立的顶级工作区或导航栏目。
- 不把岗位匹配与直接投递合并为同一个领域服务。
- 不在当前会话中静默同步后续知识库变更。
- 不扩大首期 ATS 支持范围；仍仅正式支持 Moka/Mokahr 中文岗位页和 DJI 招聘路径。
- 不自动创建、自动执行或自动提交投递任务。

## 用户流程

“新建投递”视图顶部使用 `岗位匹配 / 直接投递` 分段控件，默认选中“岗位匹配”。

岗位匹配流程：

1. 前端读取知识库中的岗位期望事实。
2. 面板展示目标岗位、地点、用工类型、行业、办公方式和薪资六类期望。
3. 用户核对、补充或修改期望，并输入招聘链接。
4. 前端先保存或确认岗位期望，全部成功后调用 `JobMatchApi.create()`。
5. 后端重新从知识库生成岗位期望快照，并在获取浏览器租约前验证快照非空。
6. 后端打开链接并识别入口类型。
7. 岗位列表或岗位详情创建 `JobMatchSession`，前端跳转到 `/job-match-sessions/:sessionId`。
8. 投递表单不创建会话；前端切换到“直接投递”并预填链接，仍由用户填写任务名称并确认创建任务。

直接投递流程保持现状，只增加接收预填链接的能力。

## 岗位期望核对

用户界面不展示 `extracted`、`user_confirmed` 或 `user_corrected` 等内部状态。事实按来源呈现：

- 用户已填写或修改并保存的值直接显示为可用值。
- 简历抽取但尚未核对的值预填，并标记“来自简历，待确认”。
- 缺失值显示为空，可在入口面板中填写。

提交时按字段执行最小写入：

- 未修改的简历抽取值调用现有事实确认接口。
- 修改或新填写的值调用现有档案保存接口。
- 已保存且已核对的值不重复写入。
- 空字段不写入；六类期望中至少一项必须非空。

只有所有必要写入都成功后才能创建匹配会话。任一写入失败时保留面板草稿，不获取浏览器租约，也不创建会话。面板记录每个成功写入返回的最新事实，重试时只提交仍待处理的字段，避免对已经保存的修改重复增加事实版本。

岗位期望有效性使用共享纯函数判断，避免 Web 预检与 API 最终校验采用不同的字段集合或状态规则。后端校验是权威边界，前端校验只用于提前反馈。

### 字段规范化

六类岗位期望使用以下知识库规范路径：

- `preferences.targetRole` -> 目标岗位。
- `preferences.targetCity` -> 地点。
- `preferences.employmentType` -> 用工类型。
- `preferences.industry` -> 行业。
- `preferences.workMode` -> 办公方式。
- `preferences.salary` -> 薪资。

当前档案字段注册表缺少行业、办公方式和薪资的完整可编辑定义，本增量补齐这些定义。当前岗位匹配快照使用的 `preferences.location` 与档案现有的 `preferences.targetCity` 不一致，本增量统一新写入和新快照为 `preferences.targetCity`，读取时继续把旧 `preferences.location` 作为地点别名，避免已有本地事实失效。

当规范路径和旧别名同时存在时，选择顺序固定为：已由用户核对的事实优先于仅抽取事实；状态层级相同时规范路径优先于旧别名；仍相同时选择较高 revision。确认或编辑后只写规范路径；旧别名事实可以保留，但共享岗位期望投影必须稳定忽略已被规范路径覆盖的旧值。

## 组件与依赖边界

### 工作区

`ProfileApplicationWorkspace` 接收并向下传递 `JobMatchApi`，管理以下页面级状态：

- 当前模式：`job_match` 或 `direct_application`。
- 识别为投递表单后需要回填的链接。

工作区负责模式切换和路由跳转，不负责岗位期望持久化或会话创建细节。

### JobMatchStartPanel

新增 `JobMatchStartPanel`，职责限定为：

- 读取并展示岗位期望。
- 管理岗位期望草稿和招聘链接。
- 校验 HTTP/HTTPS 链接及至少一项非空期望。
- 确认或保存岗位期望。
- 调用 `JobMatchApi.create()`。
- 将创建结果通过回调交给父组件。

面板不直接操作路由，不创建 `ApplicationTask`，也不承载匹配工作台逻辑。

### ApplicationStartPanel

现有组件继续只创建直接投递任务。新增受控的初始链接输入，使父组件在入口识别为投递表单时可以切换模式并预填链接。预填不能自动提交表单，也不能绕过任务名称校验。

### API 服务

`JobMatchService.create()` 在获取 `BrowserOwnershipLease` 之前生成并验证岗位期望快照。空快照抛出稳定错误 `job_expectation_required`，路由映射为可恢复的客户端错误。该路径不得调用浏览器、写入会话或记录包含用户事实的 trace。

## 会话内的网站筛选确认

开始匹配前的确认针对“我的岗位期望”；创建会话后的确认针对“招聘网站将如何执行筛选”。两者不能混为同一次写入。

工作台展示会话快照及 Adapter 的网站筛选映射：

- 可映射条件显示将写入的网站筛选项。
- 网站无法表达的条件显示为仅本地匹配。
- 岗位期望值和映射结果在该步骤只读。
- 用户确认映射后才读取筛选后的全部岗位。

如需修改岗位期望，用户返回候选人档案更新后重新创建匹配会话。知识库后续变化不静默修改当前会话。

## 状态与并发

`JobMatchStartPanel` 分别跟踪档案加载、事实保存和会话创建状态。任一写操作进行中时锁定相关控件和主操作按钮，防止重复创建。

组件卸载或输入上下文变化后，过期请求结果不得覆盖当前草稿。创建成功只处理一次：会话结果触发工作台导航，投递表单结果触发模式切换和链接回填。

## 错误处理

- 档案读取失败：禁止开始匹配并提供重试。
- 岗位期望为空：提示至少填写一项，并将焦点移到第一个期望字段。
- 岗位期望保存失败：不创建会话，保留全部草稿供重试。
- 后端返回 `job_expectation_required`：刷新岗位期望状态并显示相同的用户引导。
- 链接格式错误：前端拦截并将焦点移到链接输入框。
- `browser_task_in_use`：提示先处理当前投递或匹配任务，不抢占浏览器。
- `unsupported_job_entry`：说明当前正式支持的站点与页面范围，不自动改为直接投递。
- 网络或服务异常：保留输入，允许原地重试。
- 识别为投递表单：作为正常分流处理，不显示错误。

用户界面只显示可理解的中文提示，不直接显示内部事实状态、异常消息或错误码。

## 响应式与可访问性

- 分段控件使用可识别的选中状态和键盘可操作按钮。
- 所有输入具有明确标签，异步错误使用 `role="alert"`，加载状态可被辅助技术读取。
- 固定格式控件具有稳定尺寸；在 320px 宽度下不产生横向溢出。
- 长链接、错误信息和按钮文字允许换行，不与相邻控件重叠。
- 保存或创建期间禁用会导致重复写入的操作，但保留清晰的忙碌状态。

## 测试策略

实现严格遵循 TDD，按以下层次验收：

1. 共享领域测试：岗位期望字段识别、空值处理、抽取值待确认、已保存值复用、`targetCity` 与旧 `location` 的确定性优先级。
2. API 服务与路由测试：空岗位期望返回稳定错误；断言浏览器租约、页面打开和会话写入均未发生。
3. `JobMatchStartPanel` 测试：读取失败、确认抽取值、保存修改值、重复提交锁定、失败后保留草稿和正常创建分流。
4. 工作区与路由测试：默认岗位匹配、切换直接投递、创建后导航、投递表单链接回填。
5. 工作台测试：网站筛选映射只读，不能在会话内修改知识库期望。
6. 样式测试：320px 无横向溢出，长内容可换行。
7. Synthetic ATS E2E：从主界面输入招聘链接开始，完成期望确认、会话创建、网站筛选映射确认和岗位读取；全程断言 `submissionCount === 0`。
8. 回归验证：岗位匹配定向测试、全量测试、类型检查和生产构建。

真实 Moka/DJI 页面继续作为后续人工只读验收，Synthetic ATS 结果不得表述为真实网站验收通过。

## 完成标准

- 用户可以从主界面完整创建岗位匹配会话。
- 简历抽取的岗位期望在使用前经过用户明确核对。
- 岗位期望变更先写回知识库，再生成不可静默变化的会话快照。
- 空岗位期望不会获取浏览器租约或创建会话。
- 投递表单入口只回填直接投递表单，不自动创建任务。
- 网站筛选映射确认后才读取筛选后的全部岗位。
- 所有自动化测试、类型检查和构建通过，Synthetic ATS 全程零提交。
