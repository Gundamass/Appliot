# 候选人档案统一工作区设计

## 1. 背景与目标

当前候选人档案页面同时展示长表单、字段确认状态、字段证据和资料审核内容，造成语义重复和信息噪声。用户保存档案后，档案内容本身就应当被视为用户确认过的长期资料；PDF 原文位置则不属于日常档案编辑流程，而属于投递时判断字段映射是否合理的依据。

本次调整目标：

1. 将候选人档案变成唯一的个人资料编辑中心。
2. 保留全局简历解析入口，但不在每个栏目重复显示。
3. 移除档案页字段级“已确认、待确认、查看来源”等重复信息。
4. 将招聘网站字段、档案字段、匹配依据和人工审核集中到投递任务页面。
5. 保留用户在保存前检查和补全资料的能力，并让未保存状态清晰可见。

## 2. 非目标

- 不改变受控浏览器的自动填写和禁止最终提交规则。
- 不在本次设计中重新实现 PDF OCR、文本解析或证据定位算法。
- 不自动生成或改写实习描述、项目描述和项目要点。
- 不删除现有 `EvidenceDrawer` 的 PDF 高亮能力；它由投递审核场景继续使用。

## 3. 页面信息架构

### 3.1 全局应用导航

保留三个一级入口：

- 候选人档案
- 投递任务
- 任务审核

“字段证据”不再作为独立一级入口。

### 3.2 候选人档案页

档案页由四层组成：

1. 顶部应用导航：提供页面级切换。
2. 全局档案信息栏：展示候选人姓名、目标岗位、档案完整度、待补资料数量、最近保存时间，以及全局“简历解析”和“补全资料”操作。
3. 左侧档案目录：按栏目切换基本信息、求职偏好、教育经历、实习与工作、项目经历、在校实践、获奖经历、技能与证书、自我评价。
4. 中央编辑区：只展示当前栏目表单或重复经历编辑器。

全局信息栏固定在应用导航下方，但不使用浏览器固定定位；移动端改为纵向堆叠。

## 4. 档案页交互设计

### 4.1 简历解析

“简历解析”是全局入口，只出现一次。点击后展开解析面板，面板包含：

- 当前简历文件名。
- 最近解析时间。
- 已提取资料数量。
- 查看解析结果。
- 重新解析。
- 收起面板。

解析结果按照字段语义写入对应档案栏目，而不是汇总到“其他字段”。重新解析只能更新解析草稿或提示冲突，不应无提示覆盖用户已经保存的资料。

### 4.2 编辑与保存

- 表单支持直接编辑、增加、删除和排序重复经历。
- 用户修改任意字段后，全局信息栏显示“有未保存的更改”。
- 点击“保存档案”保存全部改动；栏目内可提供“保存本节”作为快捷操作。
- 保存成功后显示“所有更改已保存”，不再额外显示“已确认”状态。
- “撤销修改”只撤销当前尚未保存的本地修改，不回退已保存档案。
- 必填字段为空时，在字段本身显示校验信息；不使用“待确认”替代空值提示。

### 4.3 栏目内容规则

- 项目经历字段顺序：项目名称、开始时间、结束时间、项目描述、技术栈、项目要点。
- 实习与工作字段顺序：公司名称、职位名称、开始时间、结束时间、职责和成果。
- 教育经历按学校分组，分别维护学校、专业、学历、时间、课程等字段。
- 获奖经历独立成栏，支持奖项名称、获奖时间、奖项级别、奖项描述。
- 实习描述、项目描述和项目要点默认使用用户资料，不由档案页 AI 自动生成或微调。
- 自我评价作为独立栏目维护；岗位相关微调仅在投递任务中产生候选版本并交由用户审核。

## 5. 投递任务中的映射与证据

投递任务页面接收招聘网站当前页面字段，并完成以下流程：

1. 读取候选人档案中已保存的结构化资料。
2. 识别招聘字段语义和控件类型。
3. 使用字段别名、规则和 RAG 检索寻找档案字段映射。
4. 对映射结果进行相似度阈值、字段类型和必填性验证。
5. 高置信度映射允许自动填写，中低置信度映射进入待审核列表。
6. 在投递审核界面展示招聘字段、拟填写值、档案字段、匹配理由和来源证据。
7. 用户审核后才允许继续受控操作；系统永远不执行最终提交。

`EvidenceDrawer` 继续用于投递审核中的 PDF 原文查看和高亮定位。档案页不再渲染字段级证据入口。

## 6. 数据与状态边界

档案保存状态与投递映射状态分离：

- 档案状态：`未保存`、`已保存`、`解析草稿`、`解析冲突`。
- 投递字段状态：`未映射`、`候选映射`、`已填写`、`需审核`、`用户修改`。

档案保存不等于投递字段审核通过；它只表示用户确认了自己的资料。投递任务仍需独立审核招聘网站字段和自动填写结果。

解析结果建议保留文档版本和字段来源元数据供投递审核使用，但这些元数据不在档案表单中逐项展示。

## 7. 错误与边界处理

- PDF 解析失败：全局解析面板展示失败原因，并允许重新上传或重试。
- 解析出与已保存资料冲突的值：标记为“解析冲突”，提供保留档案值或采用解析值的选择。
- 用户离开页面存在未保存修改：提示保存、放弃或继续编辑。
- 档案缺少投递必填字段：投递任务显示缺失字段并提供跳转到对应档案栏目，不直接猜填。
- 投递映射低于相似度阈值：保持为空并请求用户补充或选择映射。
- 投递页面中的用户临时修改只属于当前任务，不回写候选人档案，除非用户明确选择保存到档案。

## 8. 测试范围

### 档案页面

- 全局信息栏正确展示完整度、待补资料、解析入口和最近保存时间。
- 栏目切换只更换中央编辑区，解析入口保持全局唯一。
- 输入修改后显示未保存状态，保存后恢复已保存状态。
- 空必填字段显示字段校验，不显示字段确认状态。
- 重复经历的新增、编辑、删除和排序保持分组数据结构。
- 解析面板可展开、收起、重试，并展示解析结果摘要。

### 投递任务

- 读取已保存档案并生成招聘字段候选映射。
- 低置信度、类型冲突和缺失资料进入审核列表。
- 审核界面能够打开现有 PDF 证据抽屉并显示页码和高亮。
- 用户临时修改不会静默覆盖候选人档案。
- 最终提交按钮始终不可由自动化流程触发。

## 9. 验收标准

1. 用户进入候选人档案后，不再看到独立的“字段证据”或字段级来源列表。
2. 用户只需上传一次简历，即可通过全局解析入口将内容分配到各个档案栏目。
3. 用户点击保存后，档案页面不再要求逐字段确认。
4. 用户能快速看见缺失资料并跳转补全。
5. 用户在投递审核页能看到招聘字段与档案字段的对应关系及 PDF 证据。
6. 系统仍然在最终提交前停止，并交由用户审核。
