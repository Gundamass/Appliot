# 投递任务名称设计

## 背景

投递任务目前只保存招聘页面 URL，审核列表和任务详情主要展示网站域名。用户向同一招聘网站创建多个任务时，很难根据域名快速区分公司、岗位或投递批次。

## 目标

新建投递时提供可修改的任务名称，并将名称长期保存在本地数据库。任务名称用于本地任务识别，不会写入招聘网站表单，也不参与自动提交。

## 新建交互

新建投递表单增加“任务名称”输入框：

- 用户粘贴招聘链接后，系统根据 URL 自动生成建议名称。
- DJI 链接建议“大疆校招投递”；其他链接使用可读的网站名称或域名生成建议。
- 用户可以覆盖自动建议。
- 名称去除首尾空白后必须包含 1–80 个字符。
- 用户已经手动修改名称后，继续修改 URL 不覆盖用户输入。

## 数据模型

`ApplicationTaskInput` 和 `ApplicationTask` 增加 `name` 字段。SQLite 的 `application_tasks` 表增加可空的 `name` 列，以兼容已有任务。

新任务必须写入非空名称；历史任务读取到空名称时，由 API 根据 `applicationUrl` 生成显示名称。这样前端始终收到可展示的名称，同时不要求用户迁移或重新创建旧任务。

## 展示位置

- 投递审核列表：任务名称作为卡片主标题，网站域名和 URL 作为次级信息。
- 投递任务详情：任务名称作为页面标题，URL 保留用于确认目标网站。
- 删除确认：文案包含任务名称，降低误删风险。

## 错误与兼容

- 名称缺失、全为空白或超过 80 个字符时，创建接口返回输入无效。
- 数据库迁移采用新增可空列，不修改历史行。
- 历史任务使用 URL 派生名称，不显示空标题。
- 名称不参与浏览器 Worker、字段匹配、RAG 检索或招聘网站填写。

## 测试范围

- 契约接受合法名称并拒绝空白或超长名称。
- 数据库仓库写入、读取和列出任务名称，并兼容历史空值。
- 创建 API 持久化名称并在响应中返回名称。
- 新建表单根据 URL 生成建议名称，且不覆盖用户手动输入。
- 审核列表和任务详情优先展示任务名称。
