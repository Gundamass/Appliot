# 档案驱动的动态表单填充设计

## 背景

真实 DJI 投递页面已经能够完成基础字段填充，但仍存在五类高频缺口：可选字段未充分匹配、条件区块展开后未继续填写、可搜索下拉框仅输入未选中、重复经历未按档案数量新增，以及运行中的投递任务不能及时使用最新候选人档案。

本次改进不改变“用户自行登录和选择岗位、系统只负责简历表单、永不提交”的职责边界。目标是让系统依据候选人档案尽可能完成整张表单，用户主要参与最终审核。

## 设计目标

1. 页面上所有空白且可安全操作的字段都进入精确匹配和语义检索，不以是否必填决定是否尝试填写。
2. 页面字段必须先获得包含区块、条目序号和字段分量的精确语义，再从档案或 RAG 中取值。
3. 自定义下拉框必须完成“打开、输入过滤、选择候选、回读确认”全过程。
4. 条件区块和重复区块发生结构变化后必须重新观察，并在有限轮次内继续填写。
5. 用户保存候选人档案后，活动任务应重新匹配尚未解决的字段，但不得覆盖页面上已有值。

## 核心流程

### 1. 全字段候选集合

每轮观察将全部可见、可编辑且当前为空的非法律承诺字段加入候选集合，不区分必填与可选。必填属性仅影响最终处理方式：必填字段无可靠答案时提出问题；可选字段无可靠答案时保留为空并进入最终审核摘要。

每个候选字段按以下顺序处理：

1. ATS 规则和字段别名的确定性语义映射。
2. 区块、条目序号、日期分量等上下文投影。
3. 档案精确路径查询。
4. 关键词和向量检索的语义兜底。
5. 候选值类型、选项和页面回读验证。

低于置信阈值或无法通过页面约束验证的值不自动填写。

### 2. 精确语义投影

经历型字段必须保留完整路径。例如：

- `赛事名称` -> `awards[0].name`
- `赛事时间 年` -> `awards[0].date.year`
- `赛事时间 月` -> `awards[0].date.month`
- `赛事描述` -> `awards[0].description`
- `项目名称` -> `projects[1].name`

日期控件不能接收完整日期字符串后自行猜测。系统根据页面控件的年、月、日角色投影对应分量，并使用页面可选项验证该分量。

页面标签本身不完整时，观察器需要保留最近的区块标题、条目边界和同组字段信息。RAG 负责处理“赛事名称”和“获奖名称”等语义差异，但不能替代日期分量和条目序号等结构判断。

### 3. 可搜索下拉框

自定义下拉框的成功条件不是输入框出现文本，而是页面控件显示已选择的候选值。统一执行协议为：

1. 点击控件打开候选面板。
2. 在支持搜索时输入规范化目标值，以缩小候选范围。
3. 优先点击文本完全匹配的候选项，其次使用经过校验的标准化等价项。
4. 等待面板关闭或选中状态出现。
5. 重新观察，并对展示值做规范化回读比较。

找不到可靠候选项时，记录 `option_not_found`，不得将搜索文本当作已填结果。

### 4. 条件区块

布尔选择会动态展开字段时，系统使用档案事实推断选项：

- 档案存在对应经历条目：选择“是”。
- 档案明确为空或明确记录没有该经历：选择“否”。
- 档案无法判断：保持为空，在最终审核中提示。

“实验室经历”对应科研、实验室或研究经历集合。选择“是”后，系统等待 DOM 稳定并重新观察新字段，再以同一条目语义进行填写。每次结构变化都会开启新的有限填充轮次，防止无限循环。

### 5. 重复经历补齐

系统按区块分别比较档案条目数和页面条目数，支持教育、工作或实习、项目、获奖以及实验室经历。仅当档案条目数更多、页面存在安全的“添加”操作时，逐次点击并在每次点击后重新观察。

系统只补齐到档案条目数，不删除页面条目，也不覆盖用户已填写内容。经历按候选人档案的既定时间顺序映射；项目继续遵循档案中的时间排序规则。

### 6. 档案热同步

字段解析每次都从资料仓库读取最新事实，不保存独立的旧档案副本。候选人档案保存成功后，API 向活动任务发送档案修订通知：

1. 递增档案修订号。
2. 使任务中 `missing`、`unsupported`、`deferred` 和未成功回读的字段决策失效。
3. 保留页面已有值、任务级答案和已确认成功的字段。
4. 若任务处于等待资料或观察状态，自动重新观察并运行填充；若浏览器正在被用户操作，则待操作静默后运行。

该机制只重新处理未解决字段，不会因为档案修改而覆盖招聘页面中的用户输入。

## 安全与失败处理

- 提交、确认投递和等价终态操作继续由策略层强制阻断。
- 动态填充设置最大结构扩展次数和最大语义轮次；超过上限后暂停并显示具体区块。
- 每个控件操作必须回读；失败不得计为已填。
- 页面已有非空值视为用户或招聘系统数据，默认不覆盖。
- 低置信语义匹配只进入最终审核，不自动写入页面。
- 用户操作会使当前自动化执行失效，等待页面稳定后重新观察。

## 测试与验收

### 单元测试

- 获奖名称、描述和日期年/月生成不同的精确路径。
- 可搜索下拉框只有点击候选并成功回读时才返回成功。
- 实验室档案存在、明确为空和未知分别得到“是”“否”和不操作。
- 重复区块按照档案数量逐项新增，达到数量后停止。
- 档案修订只使未解决决策失效，不覆盖已存在页面值。

### 集成测试

- 模拟选择“有实验室经历”后出现新字段，验证重新观察和二次填写。
- 模拟三个项目但页面初始两个项目，验证点击一次添加并填写第三项。
- 模拟搜索型年份下拉框，验证输入 `2024` 后必须点击 `2024` 候选。
- 模拟任务运行期间更新获奖信息，验证恢复后使用最新档案。

### 真实页面回归

在 DJI 测试实例中验证：

1. 必填和有档案证据的可选字段均被处理。
2. 赛事名称、年份、月份和描述与档案一致。
3. 教育、项目、获奖等重复经历数量与档案一致。
4. 条件区块展开后新字段被继续填写。
5. 修改档案并保存后，未解决字段能够重新匹配。
6. 全流程停在用户审核阶段，系统不触发提交。

## 非目标

- 不替用户选择岗位、登录或处理验证码。
- 不自动生成或改写项目亮点、实习职责和成果。
- 不为档案中不存在且无法可靠推断的信息编造答案。
- 不针对当前截图重写整个表单自动化架构。
