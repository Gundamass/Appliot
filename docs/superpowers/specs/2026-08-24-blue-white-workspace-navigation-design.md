# 对话优先工作区与招聘入口发现设计

## 目标

把“发现企业校招入口 -> 询问是否岗位推荐 -> 展示推荐岗位 -> 用户确认后受控投递”串成一条对话流程，同时将对话首页、投递进度、我的简历和受控投递详情统一到蓝白工作区。独立的“我的岗位/岗位推荐”导航和页面退出主流程。

## 已确认边界

- 左侧导航只保留“对话首页”“投递进度”“我的简历”。
- 对话首页保留“岗位推荐”和“投递进度”快速开始卡片。
- 用户可直接说“帮我投递百度校园招聘”等公司级意图。
- 系统通过受控浏览器搜索“公司名 + 校园招聘 + 官网”，排除广告和不安全地址后打开第一个有效自然结果。
- 搜索结果先以招聘入口卡片展示并要求确认；确认后才询问是否做岗位推荐。
- 百度校招岗位由专用适配器读取，随后复用现有岗位匹配、岗位选择、受控填写及最终提交锁定逻辑。
- 登录、验证码等交互由用户接管；系统不自动绕过挑战，也不自动最终提交。
- `/job-match-sessions/:sessionId` 和 `/applications/:taskId` 保留。
- `/applications/new`、`/?view=jobs` 和 `/?view=apply` 回到对话首页。
- 浏览器搜索是当前主路径；搜索 API 仅作为未来备用，不在本期实现。
- 本期不实现企业招聘状态跟踪。

## 端到端流程

```text
用户：帮我投递百度校园招聘
  -> 识别 company=百度, recruitmentType=campus
  -> 受控浏览器搜索“百度 校园招聘 官网”
  -> 排除广告、非 HTTPS、内网和异常链接
  -> 打开第一个通过校验的自然结果
  -> 对话展示“百度校园招聘入口”卡片
  -> 用户确认该入口
  -> 对话询问“是否先做岗位推荐？”
       -> 否：保留入口，不创建推荐或投递任务
       -> 是：创建岗位匹配会话
            -> 如需登录/验证码，用户接管
            -> 百度适配器读取岗位
            -> 复用现有评分生成推荐卡片
            -> 用户选择岗位
            -> 复用现有受控投递确认和任务卡片
```

## 受限浏览器入口发现

新增封闭 Worker 操作 `search_recruitment_site`，输入仅包含 `ownerId`、公司名和固定招聘类型 `campus`，输出为已打开并校验的招聘入口。它不是通用浏览器工具，不接受任意查询、选择器、点击坐标或脚本。

安全与确定性约束：

- 查询由 Worker 固定组装为“公司名 校园招聘 官网”。
- 公司名去除控制字符并限制长度。
- 只读取自然搜索结果，过滤带“广告/推广”标记的结果。
- 最多检查三个自然结果，按页面顺序处理。
- 只接受 HTTPS 目标；拒绝 URL 凭据、localhost、环回、私网、链路本地地址。
- 搜索页和目标页均设置超时，结果文本和数量有上限。
- 点击/打开候选后按最终重定向地址再次校验。
- 返回公司、查询词、标题、最终 URL 和域名；不返回搜索页的任意 DOM 或敏感内容。
- 搜索任务完成后由调用方释放 `ownerId`，再把已确认 URL 交给岗位匹配会话，避免单浏览器租约冲突。

## 百度岗位适配

新增 `baiduJobAdapter`，支持 `talent.baidu.com` 的校园招聘岗位列表和岗位详情入口。适配器沿用 `JobPageSnapshot -> JobPostingDraft` 边界，不直接控制浏览器，也不改变评分模型。

- 来源标识和适配版本固定为百度专用值。
- 映射关键词、工作地点和招聘类型筛选条件。
- 从百度岗位卡片或详情快照提取岗位标识、标题、地点、描述、要求和规范 URL。
- 对缺失字段保持保守降级；无法确认是岗位列表或详情时返回不支持，而不是猜测岗位。
- 生产依赖中与 Moka、DJI 适配器并列注册。

## 对话状态与卡片

对话契约新增两类受控步骤：

1. `recruitment_entry` 卡片：展示公司、招聘类型、标题、域名和入口 URL，允许用户确认或取消。
2. `recommendation_offer` 确认：入口确认后询问是否创建岗位推荐。

工具链新增：

- 发现招聘入口。
- 确认入口并保存到当前对话上下文。
- 基于已确认入口创建岗位匹配会话。
- 读取匹配结果并继续使用现有推荐卡片和 `start_application` 确认。

幂等性以对话线程、公司和确认入口为边界；重复确认不得重复创建岗位匹配或投递任务。

## 工作区结构

采用共享 `WorkspaceFrame`：

```text
WorkspaceFrame
├── 蓝白顶部栏
├── 左侧导航
│   ├── 对话首页
│   ├── 投递进度
│   └── 我的简历
├── 当前页面主内容
└── 可选右侧上下文（仅对话首页）
```

`ChatHome`、进度/简历视图和任务详情只提供内容，不再分别维护不同外壳。移动端导航改为横向紧凑布局，页面不得产生水平溢出。

## 错误处理

- 搜索无自然结果：对话说明未找到可靠官网，不进入岗位匹配。
- 搜索页验证码：保持浏览器窗口并提示用户接管，完成后可重试。
- 目标 URL 校验失败：跳过当前候选并检查下一个，全部失败后返回结构化错误。
- 招聘站不受支持：展示已找到入口，但明确说明暂不能自动推荐，可保留人工打开入口。
- 百度页面结构变化：适配器返回可诊断的不支持结果，不生成伪造岗位。
- 任何失败都不得创建投递任务或触发最终提交。

## 验证

- 契约测试覆盖封闭请求/响应、长度限制和拒绝额外字段。
- Worker 单元测试覆盖查询组装、广告过滤、候选顺序、重定向后校验及无结果。
- API 客户端测试覆盖 IPC 请求、响应解析和租约释放。
- 百度适配器使用固定快照覆盖列表、详情、筛选映射和不支持页面。
- 对话图测试覆盖公司意图、入口确认、岗位推荐确认、取消、幂等及现有投递确认。
- 前端测试覆盖新卡片、三项导航和旧地址回退。
- 全量测试、类型检查、`git diff --check`，并用桌面和移动视口做视觉验证。
