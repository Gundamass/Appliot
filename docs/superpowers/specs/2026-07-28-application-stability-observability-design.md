# 投递自动化稳定化与实时感知设计

**日期：** 2026-07-28
**状态：** 已确认
**适用计划：** 在 `2026-07-22-resume-assistant-integration.md` 的 Task 3 与 Moka 适配器之间插入稳定化任务

## 目标

让本地助手能够实时感知受控浏览器中的用户选岗、登录、输入和页面跳转，并以简洁方式展示当前动作、执行进度和卡点。任何浏览器操作必须在有限时间内成功、失败或进入可恢复暂停，不能无限显示“处理中”或“正在填写”。

## 非目标

- 本任务不实现 Moka 或北森的完整站点适配器。
- 本任务不增加最终提交能力。
- 本任务不让模型持续观察浏览器，也不把密码、验证码或完整敏感值发送给模型。
- 本任务不实现面试官 Agent 或 Skill Harness。

## 已确认的产品行为

1. 默认采用自动继续模式。用户完成选岗或登录并进入稳定页面后，助手自动重新观察、分析并继续填写。
2. 检测到用户点击或输入时，自动化立即避让。用户已经填写的非空字段不会被覆盖。
3. 登录、密码、验证码、扫码、CAPTCHA 和 MFA 始终由用户完成。
4. 页面监听、稳定判断、字段变化和进度推送均在本地完成，不调用 DeepSeek。
5. 只有新页面中的未知字段、开放题或需要岗位微调的内容才允许批量调用一次模型。
6. 最终审核页必须进入 `review_locked`，不存在自动提交命令。

## 方案选择

采用“浏览器事件监听 + 结构指纹 + 稳定后观察”的混合方案。

不采用固定频率调用模型，也不持续比较完整 DOM。Worker 监听 Playwright 导航事件和页面内用户活动信号；相关变化经过防抖后，只对可见表单结构生成轻量指纹。结构指纹变化或页面阶段变化时才生成新快照并通知 API。

## 架构

### Browser Activity Monitor

Browser Worker 新增独立的活动监视器，职责如下：

- 监听页面主框架导航、URL 和标题变化。
- 监听页面内可见表单结构变化。
- 识别用户点击、输入和提交动作，但不采集密码、验证码或具体输入值。
- 识别页面稳定、浏览器断开和页面关闭。
- 在自动化命令开始、成功、失败和超时时产生执行事件。

监视器只发布结构化事件，不调用模型，也不执行表单修改。

### 页面稳定与指纹

- 相关页面事件发生后防抖 750 毫秒。
- 使用 URL、页面阶段、可见字段类型、可访问标签和可见操作生成结构指纹。
- 连续两次相隔 500 毫秒的结构指纹一致时判定页面稳定。
- 稳定等待硬上限为 5 秒。超出后以当前结构生成快照，并标记 `page_unstable`，由 API 决定继续观察或暂停。
- 相同站点和相同结构指纹复用字段语义映射；用户输入变化不使结构指纹失效。
- CSS 隐藏、不可交互、禁用和内部控件不进入可填写字段集合。

### API Stability Coordinator

API 新增稳定化协调器，接收 Worker 活动事件并维护服务器权威的任务进度：

- 当前页面阶段。
- 当前字段序号与总字段数。
- 当前操作、开始时间和超时截止时间。
- 最近一次成功结果。
- 当前卡点、错误代码和可恢复动作。
- 浏览器最后活动时间与连接状态。

协调器负责去重、持久化和通过 SSE 发布事件。前端不自行推断命令或任务状态。

### 自动恢复

恢复遵循以下规则：

1. 用户活动出现时，暂停新的自动化操作并等待 750 毫秒静默窗口。
2. 用户输入后的字段回读为非空且校验无错误时，将其标记为“用户已填写”并跳过。
3. 页面导航后等待稳定，再重新观察并比较页面阶段与结构指纹。
4. 登录页离开后自动恢复任务，不要求用户点击“我已完成登录”。
5. 当前字段超时或回读不一致时停止后续字段，进入可恢复暂停。
6. 用户手动修正字段后，回读通过则自动继续剩余字段。
7. 浏览器断开时暂停任务；重连后必须重新观察并通过检查点匹配才能恢复。

## 超时预算

| 操作 | 超时 |
|---|---:|
| 页面观察 | 10 秒 |
| 文本、日期、单选、复选、下拉填写 | 15 秒 |
| 文件上传 | 60 秒 |
| 中间保存或下一页点击 | 30 秒 |
| 页面稳定判断 | 5 秒 |
| Worker IPC 请求 | 对应操作超时加 2 秒 |

超时后必须发布失败事件并释放前端忙碌状态。自动重试最多一次，且仅限重新观察后目标字段仍存在、页面指纹匹配并且操作属于安全编辑。文件上传和中间点击不自动重试。

## 事件模型

保留 `state_changed` 作为粗粒度状态事件，增加进度事件。事件均包含 `id`、`taskId`、`createdAt` 和服务器序号。

进度事件类型限定为：

- `browser_activity`：用户活动、页面导航、页面稳定、浏览器连接变化。
- `operation_started`：字段填写、上传、验证或中间导航开始。
- `operation_completed`：操作成功并完成回读。
- `operation_failed`：超时、字段消失、回读不一致或页面错误。
- `task_paused`：等待登录、等待用户、卡点或浏览器断开。
- `task_resumed`：页面重新稳定且检查点匹配后恢复。

事件日志保留最近 200 条，沿用现有 SSE 重放和历史缺口重置机制。

## 简洁界面

默认页面只展示三类信息：

1. 当前动作，例如“正在填写：手机号码”。
2. 当前进度，例如“第 5 / 8 项，已运行 2.1 秒”。
3. 最近结果，例如“上一项：邮箱已填写并验证成功”。

用户可执行的主要动作：

- 暂停自动填写。
- 重试当前字段。
- 在浏览器中手动处理。
- 取消任务。

“查看执行记录”默认折叠，展开后只显示最近 5 条用户可理解的活动。完整事件保留在服务端，不在主界面堆叠。底部阶段总览压缩为：连接浏览器、用户选岗、登录认证、填写验证、最终审核。

原型中的“自动填写、用户操作、卡点诊断”切换按钮仅用于演示，生产界面不展示。真实状态由系统自动判断。

## 卡点展示

卡点页面必须回答三个问题：

1. 卡在哪里，例如“手机号码”。
2. 为什么停，例如“控件 15 秒内未返回可验证值”。
3. 用户能做什么，例如“重试当前字段”或“我来填写”。

错误文案使用中文业务描述，技术错误代码只出现在展开详情中。

## 隐私与安全

- 用户活动事件只记录字段 ID、字段标签和活动类型，不记录具体输入值。
- 密码、验证码和认证字段不生成值快照，不进入 RAG 或模型上下文。
- SSE 不传输完整简历字段值，只传状态、标签、序号和脱敏结果。
- 用户输入优先于自动化建议，非空页面值默认不可覆盖。
- 所有浏览器修改继续要求一次性操作授权。
- `terminal_submit`、任意脚本、任意选择器、坐标和 CDP 仍不可表示。

## Token 成本约束

- 页面监听、活动识别、结构指纹、进度更新和自动恢复为零模型调用。
- 相同站点与结构指纹复用语义映射。
- 一个新页面的所有未知字段合并为一次模型请求。
- 用户逐字输入、焦点变化和相同页面刷新不得触发模型调用。
- 每个页面保存本次是否调用模型及缓存命中原因，供测试验证。

## 验收标准

1. 用户从岗位页进入登录页再进入申请表时，本地助手无需手动刷新即可在 2 秒内更新页面阶段。
2. 用户在受控浏览器输入内容时，助手在 1 秒内显示“用户正在操作”并停止覆盖该字段。
3. 每个自动化操作在规定超时内进入成功、失败或可恢复暂停，不能无限保持忙碌。
4. 页面展示当前字段序号、当前动作、耗时和最近结果；详细记录默认折叠。
5. 相同结构指纹的重复观察不调用 DeepSeek；用户输入不会触发 DeepSeek。
6. 字段写入后必须回读验证，失败时停止后续操作并指出具体字段。
7. 浏览器断开、页面关闭和 Worker 崩溃均能在前端显示明确状态并释放忙碌按钮。
8. 用户手动完成卡点字段后，助手能够检测有效值并继续剩余字段。
9. 所有合成 ATS 流程最终停在 `review_locked`，服务器提交计数保持为零。

## 测试范围

- Worker 单元测试：导航、输入、DOM 变化、防抖、稳定指纹、敏感字段脱敏。
- API 单元测试：事件去重、超时、单次重试、暂停恢复、检查点和 SSE 重放。
- Web 组件测试：简洁状态、卡点操作、折叠详情、断线和任务切换竞态。
- 合成 ATS 端到端测试：选岗、登录、用户手动输入、自动恢复、字段超时、人工修正和最终审核锁定。
- Token 行为测试：相同指纹与用户输入事件不会调用模型，新页面未知字段只批量调用一次。

## 实施顺序

1. 扩展进度事件合同和持久化。
2. 实现 Browser Activity Monitor 与稳定指纹。
3. 实现协调器、超时和恢复状态。
4. 接入 SSE 和简洁任务界面。
5. 扩展合成 ATS 与端到端验收。
6. 通过稳定化验收后再开始 Moka 专用适配器。
