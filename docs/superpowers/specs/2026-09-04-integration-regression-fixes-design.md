# 前后端联调回归缺陷修复设计

## 背景

2026-09-04 的生产构建、真实 HTTP/UI 联调和浏览器功能测试确认了三项问题：

1. 前端“投递进度”快捷入口发送“我投了哪些岗位？对应的网站有哪些？”后，确定性规则识别为投递任务查询，但真实结构化模型返回 `list_recommendations` 并覆盖了正确结果。
2. 服务守护器已经退出时，`services:status` 仍展示运行状态文件中的历史 `ready` 值，与实际端口不可访问的状态矛盾。
3. Windows 测试默认硬编码系统 Edge；本机 Edge 151 与 Playwright 1.53 对应的 Chromium 138 存在启动不稳定，导致浏览器测试在业务代码执行前失败。

## 目标

- 明确、低风险的对话意图不被模型的合法但错误输出覆盖。
- 服务状态输出只陈述当前可验证的状态，不把失去守护器后的缓存值显示为就绪。
- 开发和测试优先使用与 Playwright 匹配的浏览器，同时保留生产环境显式配置和系统浏览器回退能力。
- 用自动化回归与真实隔离服务联调证明修复有效。

## 非目标

- 不重构整个对话意图体系或服务守护器架构。
- 不增加远程服务探测协议或新的后台常驻进程。
- 不改变最终提交审批、安全边界或生产浏览器的显式配置接口。

## 设计

### 1. 确定性意图优先级

`classifyIntent` 继续先计算 `deterministicIntent`。当确定性结果不是 `unknown` 时直接采用该结果，不再调用结构化模型。只有规则无法识别的消息才交给模型分类。

这样可以保证投递进度、明确的岗位推荐、任务创建和招聘官网发现等已有产品入口行为稳定；模型仍负责规则之外的自然语言表达。显式确认流程保持现状，仍由确认存储中的动作决定。

回归测试必须构造“模型返回合法但错误的 `list_recommendations`”场景，并断言“我投了哪些岗位？对应的网站有哪些？”仍执行 `list_application_tasks`，且模型未被调用。

### 2. 守护器退出后的状态降级

`Get-ServiceStatusLines` 仍验证 `supervisorPid` 对应的进程身份。当守护器不存在时：

- 守护器显示“未运行”；
- 所有受其管理的服务同样显示“未运行”，不展示缓存的 `ready`；
- 不在 `status` 命令中主动启动进程、访问 SSH 或修改运行状态文件。

守护器存活时继续展示它最近写入的服务状态和错误信息。这样保持状态命令只读、快速，并消除最危险的虚假就绪结果。

### 3. 浏览器解析顺序

浏览器选择顺序统一为：

1. `RESUME_BROWSER_EXECUTABLE` 显式配置；
2. 当前 Playwright 安装对应且文件存在的 Chromium；
3. 系统 Edge、Chrome 或 Chromium 候选路径。

Playwright 配置不再在 Windows 上硬编码 Edge；没有显式配置时使用 Playwright 默认浏览器。浏览器 Worker 的生产解析逻辑增加 Playwright Chromium 候选，但在部署包未安装该浏览器时仍自动回退到系统浏览器。

## 错误处理与兼容性

- 模型不可用或输出非法时，未知消息继续使用现有 `unknown`/回退行为。
- 没有可用浏览器时继续返回现有“未找到可用浏览器”错误。
- `RESUME_BROWSER_EXECUTABLE` 的优先级不变，运维仍可固定生产浏览器。
- 状态文件损坏时继续显示“失败”；仅守护器缺失时将缓存服务状态视为过期。

## 测试策略

按 TDD 顺序新增并先观察失败：

1. 对话图测试：错误模型结果不能覆盖明确的投递进度规则。
2. PowerShell 服务控制测试：守护器缺失且缓存服务为 `ready` 时，六行状态均不得显示就绪。
3. Playwright 配置与浏览器解析测试：无显式变量时不强制 Edge，并优先选择已安装的匹配 Chromium；显式变量仍优先。

实现后依次运行：

- 受影响的 API、浏览器 Worker、脚本单元测试；
- `pnpm typecheck`；
- `pnpm build`；
- 独立端口和临时 SQLite 上的真实前端/API HTTP 与浏览器联调；
- 完整 Playwright 功能回归；
- `git diff --check`。

联调测试创建的数据必须限定在临时目录和测试会话中，结束后停止隔离服务并删除临时数据。
