# 候选人档案与级联投递设计

## 目标

将系统从“一页 PDF 的字段镜像”升级为可长期复用的候选人投递档案。用户首次导入 PDF 后，在完整长表单中一次性确认和补充资料；后续投递不同招聘网站时，系统先填写确定字段，再仅对剩余空字段执行语义映射，最终把风险项交给用户审核，永不自动提交。

## 产品流程

```text
PDF 导入
→ 敏感信息本地提取与脱敏
→ Profile Intelligence Agent 解析非敏感经历
→ 字段标准化、证据验证和覆盖率检查
→ 完整档案表单确认与补充
→ 本地加密保存
→ 招聘网站确定性快路径填写
→ 剩余空字段语义补全
→ 动态字段重扫和回读
→ 风险聚焦审核
→ 用户自行提交
```

## 候选人档案

候选人档案由统一字段注册表驱动，首批覆盖个人信息、求职意向、教育、实习/工作、项目、在校实践、获奖、论文/专著、证书、技能、链接、附件和自我评价。字段定义包含标准路径、中文名称、别名、数据类型、所属栏目、是否可重复、敏感级别、校验规则和允许来源。

普通事实继续保留来源、证据、置信度、状态和版本。重复经历使用稳定记录标识，不依赖页面数组下标作为长期身份。用户确认或修正的事实优先级高于本地确定性提取和模型提取；新版简历与已确认值冲突时生成差异，不自动覆盖。

身份证号、电话、邮箱、详细地址等敏感值使用 AES-256-GCM 加密，数据密钥由 Windows 当前用户凭据保护。敏感字段不进入向量库、不发送给 DeepSeek、不写日志；只在授权投递任务需要时临时解密到内存。附件及元数据同样加密保存。

## Profile Intelligence Agent

Agent 只负责需要语义理解和动态修正的部分：检查文档栏目、制定解析计划、调用脱敏后的结构化抽取、检查覆盖率、定向重试遗漏栏目、匹配已有经历和生成补全问题。加密、数据库写入、冲突优先级、网页执行和提交拦截全部由确定性代码负责。

Agent 不得直接写数据库、读取敏感明文、覆盖已确认事实、自由操作浏览器或执行提交。普通简历走一次结构化抽取快路径；只有覆盖率或证据检查失败时才进入最多两轮定向修正。

## 两阶段级联补全

### 第一阶段：确定性快路径

系统只处理当前可见、可编辑、具有可靠标签且值为空的申请字段。按网站映射缓存、标准字段精确别名和明确区块规则确定语义路径，再从候选人档案中精确读取已确认值。已有官网解析值绝不覆盖。每次填写必须回读成功才计为完成。

第一阶段的未知字段只标记为待语义补全，不阻塞其他确定字段。

### 第二阶段：剩余空字段语义补全

第一阶段完成后重新观察页面，只对仍为空的合格字段检索字段注册表。映射需要同时满足 Top-1 相似度、Top-1 与 Top-2 差距、栏目兼容、控件类型兼容、选项兼容和档案中存在已确认值。阈值由标注过的招聘网站字段集校准，不使用模型自报置信度代替验证。

高置信度映射自动填写；中置信度普通字段可作为待审核草稿填写；低置信度、冲突、敏感承诺或控制页面结构的字段保持为空并聚合追问。字段路径确定后使用本地精确档案查询，不对结构化值再次运行向量检索。

填写选择项或新增经历后重新观察动态字段。单页最多执行两轮语义补全，避免无限循环。所有成功回读且通过验证的网站映射可写入本地缓存；页面结构或选项变化时缓存失效。

## 状态与人工交接

当前“一项追问阻塞整页”的行为改为先执行所有安全且确定的填写，再聚合未解决项。应用状态机需要允许从填写阶段进入追问或内容审核。没有安全中间动作、存在未解决必填项或页面结构无法稳定识别时，任务进入审核/人工接管，不以普通失败伪装结束。

最终提交、投递、确认申请及语义等价动作始终归类为终态提交。Agent、RAG、应用服务和 Browser Worker 均不暴露提交能力。

## 前端体验

候选人档案中心采用工作台式完整长表单，而不是事实卡片列表：左侧为固定栏目导航，主区展示当前栏目的全部字段和重复经历，字段旁就地显示“PDF 识别”“用户确认”“用户修正”“待补充”和“已加密”等状态。用户可以完整浏览和编辑，也可以快速定位差异与未填写项。

投递任务页压缩为四个阶段：确定性填写、语义补全、动态校验、等待审核。普通成功字段只显示数量；界面重点展示中置信度映射、敏感字段、格式转换、网站特有问题和仍为空的必填项。审核页提供字段、映射路径、值来源、置信依据和页面回读结果，但不展示不必要的敏感明文。

视觉上沿用安静、专业、工作导向的界面，允许重做现有布局和样式；不使用营销式大标题、嵌套卡片或装饰性渐变。

## 验收标准

- 官网已有值不被覆盖，未知字段不阻塞确定字段填写。
- 第一阶段后必须重新观察，第二阶段只处理仍为空的合格字段。
- 语义映射不能只凭单一相似度自动填写，必须通过类型、栏目、选项和候选差距验证。
- 结构化档案值使用标准路径精确查询；敏感字段不进入向量检索。
- 动态出现的新字段能进入后续轮次，单页轮次有明确上限。
- 每个自动填写值均有映射来源、档案证据和页面回读结果。
- 无法解决的字段集中交给用户，最终提交计数始终为零。
- 前端完整档案表单和风险审核在桌面与移动宽度下无重叠、溢出或文本遮挡。

## 分阶段实施

1. 先实现字段注册表、确定性快路径、剩余字段语义映射和级联编排，解决当前多网站字段映射与整页阻塞问题。
2. 再实现完整档案表单、稳定经历标识、Windows 密钥保护、敏感事实和附件加密。
3. 最后接入 Profile Intelligence Agent 的覆盖率规划、定向重试和技能 Harness，并扩展招聘网站回归语料。
