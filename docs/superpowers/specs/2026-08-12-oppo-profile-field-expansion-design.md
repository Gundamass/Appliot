# 候选人档案精简字段扩展设计

## 目标

以国内 ATS 的真实长表单为参考，补齐当前候选人档案缺少的通用字段，同时保留现有字段，不引入仅适用于单一公司的长期资料。

## 范围

长期候选人档案新增以下字段：

- 基础信息：个人头像。
- 教育经历：是否交流学习、是否联合办学、专业类别、学校所在地、导师姓名、是否国家重点实验室、所在实验室。
- 工作或实习经历：任职部门。
- 项目经历：项目链接，选填。

以下字段不进入长期候选人档案，招聘页面出现时作为本次投递问题交给用户填写：

- 意向面试地点。
- 招聘信息获取来源。
- 推荐码。
- OPPO 亲属信息。

## 字段语义

| 栏目 | 字段 | 标准路径 | 控件 |
|---|---|---|---|
| 基础信息 | 个人头像 | `basics.avatar` | 文件 |
| 教育经历 | 是否交流学习 | `education[].isExchange` | 是/否 |
| 教育经历 | 是否联合办学 | `education[].isJointProgram` | 是/否 |
| 教育经历 | 专业类别 | `education[].majorCategory` | 可输入文本 |
| 教育经历 | 学校所在地 | `education[].schoolLocation` | 可输入文本 |
| 教育经历 | 导师姓名 | `education[].advisor` | 文本 |
| 教育经历 | 是否国家重点实验室 | `education[].isNationalKeyLab` | 是/否 |
| 教育经历 | 所在实验室 | `education[].laboratory` | 文本 |
| 工作或实习经历 | 任职部门 | `work[].department` | 文本 |
| 项目经历 | 项目链接 | `projects[].url` | URL 文本，选填 |

头像采用本地文件资料，不能把本机绝对路径作为档案值发送给模型。后续招聘页面需要头像时，仍由受控上传策略执行。

## 项目布局

每个项目卡片使用两列网格与整行文本区域：

1. 第一行：项目名称、项目角色。
2. 第二行：项目开始时间、项目结束时间。
3. 第三行：技术栈，整行。
4. 第四行：项目链接，整行，选填。
5. 第五行：项目描述，整行多行文本。
6. 第六行：项目要点，整行多行文本。

项目要点继续作为一个完整字段保存，不拆成多个零散事实。

## 项目排序

- 项目按开始时间倒序展示，最近开始的项目在前。
- 开始时间相同时，按结束时间倒序展示。
- 缺少或无法解析开始时间的项目排在有时间项目之后。
- 两个项目均无有效时间时，保持原索引顺序，避免界面无故跳动。
- 排序只影响展示顺序，不重写 `projects[index]` 的持久化路径。

## 解析与自动填写

- PDF 中明确出现的新字段可以按现有证据规则解析，不能推断未出现的信息。
- 新字段进入现有精确映射和受约束语义映射流程。
- 布尔字段使用标准值“是”“否”，目标 ATS 的选项转换仍在投递阶段完成。
- 项目链接为空时不影响项目保存、档案完整度或自动投递。
- 被排除的公司专属字段不得通过 RAG 错配到相近的长期字段。

## 测试

- 字段注册表包含全部新增标准路径、别名和正确控件类型。
- 候选人档案可以新增、编辑、保存和删除包含新字段的重复经历。
- 项目卡片字段顺序和整行布局符合设计。
- 项目按照有效开始时间倒序展示，缺失时间稳定排在最后。
- 项目链接为空时可以正常保存，填写后可以持久化并参与字段映射。
- 排除字段不会出现在长期候选人档案中。
- 前端单元测试、类型检查和候选人档案浏览器视觉测试通过。
