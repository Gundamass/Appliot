# 投递工作台前端设计

## 目标

将投递任务页重做为一个紧凑、可扫描的工作台。用户打开页面后，第一眼能够知道：当前任务处于哪个阶段、系统正在做什么、浏览器是否在线、是否需要用户处理，以及系统是否已经到达最终审核边界。

本设计采用“左侧深色导航 + 右侧浅色工作区”的视觉方案。它服务于候选人档案、投递任务和人工审核三个长期工作流，不追求营销式展示，也不把详细事件日志堆在主视图中。

## 范围

本次只重做投递任务工作台及其共享视觉样式，保留现有 API、受控浏览器和状态机的安全边界：

- 支持确定性填写、语义补全、动态校验和人工审核四个显示阶段。
- 实时展示受控浏览器连接状态、用户活动和当前操作。
- 聚焦展示待追问、内容审核、低置信度映射、敏感字段和未填必填字段。
- 继续禁止任何自动提交、投递、确认申请或语义等价动作。
- 不在本次范围内重做候选人档案长表单的字段模型和后端存储。

## 信息架构

### 全局壳层

桌面端使用固定宽度约 232px 的深色左侧导航，主内容区使用浅灰背景和最大宽度约 1280px 的内层布局。左侧导航包含：

- 候选人档案
- 投递任务
- 审核中心
- 系统状态

导航项使用 Lucide 图标加中文名称。当前项通过高对比底色和左侧强调线标识，不使用大面积装饰图形。

移动端隐藏固定侧栏，改为顶部品牌栏和可横向滚动的页面导航；页面底部保留当前任务的主要操作区。

### 投递任务主视图

主视图由以下区域组成，顺序固定：

1. 页面标题栏：任务名称、目标网站域名、返回档案入口和取消任务入口。
2. 连接状态条：受控浏览器在线状态、当前页面标题和最近一次页面更新时间。
3. 四阶段进度条：显示完成阶段、当前阶段和未开始阶段；每个阶段只显示短标题与数量摘要。
4. 当前操作区：一句话说明系统正在做什么，附带当前操作进度和停止/恢复等允许的动作。
5. 工作区主体：左侧为“需要你处理”的风险列表，右侧为审核详情或追问表单。
6. 次级活动区：默认只显示最近三条浏览器活动，完整记录通过“查看详情”展开。

页面不默认显示完整事件流、所有成功字段或内部检索过程。成功字段只以计数和可展开摘要呈现。

## 四阶段显示模型

前端新增显示阶段，不改变后端任务状态的兼容值：

| 显示阶段 | 主要后端状态/操作 | 用户看到的含义 |
| --- | --- | --- |
| 确定性填写 | `created`、`observing_page`、`waiting_for_login`、确定性 `fill` | 系统正在处理能够明确对应的字段 |
| 语义补全 | `filling`、语义 `fill`、字段映射检索 | 系统只处理第一轮之后仍为空的字段 |
| 动态校验 | `validating`、`navigating`、页面重新观察 | 系统正在回读结果并确认页面是否发生变化 |
| 等待审核 | `needs_questions`、`awaiting_content_review`、`review_locked`、人工接管 | 系统暂停自动动作，等待用户决定 |

当前阶段由服务端进度事件中的阶段字段和操作类型推导。旧客户端只读取任务状态时仍能正常工作；新客户端优先使用阶段、当前操作和风险计数。

## 风险聚焦

主视图只突出需要用户判断的项目，按以下优先级排序：

1. 需要确认的敏感字段或求职承诺。
2. 自我评价内容审核。
3. 语义映射候选不唯一或置信度不足。
4. 网站特有问题和用户补充答案。
5. 仍为空的必填字段。

每条风险项显示中文字段名、来源类型、当前状态和下一步动作。点击后在右侧详情区展示：

- 页面原文标签和控件类型。
- 系统推断的标准字段路径。
- 候选档案值及其证据摘要。
- 相似度、候选差距或无法自动映射的原因。
- 用户可以执行的确认、修改、补充或拒绝操作。

敏感值默认部分遮罩；只有确实需要审核时才显示完整内容。日志和活动列表不显示邮箱、电话、证件号等明文。

## 实时浏览器状态

连接状态条使用四种互斥状态：

- 已连接：受控浏览器可回读页面。
- 用户操作中：检测到用户输入、点击或页面跳转，自动填写暂时暂停。
- 页面稳定：已完成重新观察，可以继续安全处理。
- 已断开：浏览器或 Worker 不可用，显示恢复入口和最近一次已保存状态。

用户在弹出浏览器中自行选择岗位、登录或跳转页面时，前端通过任务事件流更新当前页面标题、URL 摘要、活动时间和暂停原因。浏览器活动不是可点击的虚假进度，而是后端真实事件的投影。

## 视觉语言

- 左侧导航使用深炭色背景，主区使用冷白和浅灰分层。
- 主要操作使用低饱和青绿色，审核和风险使用琥珀色，错误使用红色；不使用渐变。
- 标题层级紧凑，任务页不使用超大 Hero 标题。
- 真实审核项可以使用边框容器，普通页面区域使用无框分区，避免卡片套卡片。
- 所有图标按钮使用 Lucide，并提供可读的 `aria-label` 和 tooltip。
- 固定尺寸的阶段节点、操作按钮和风险行使用稳定宽高，避免状态变化引起布局跳动。
- 文本、按钮和状态标签在 320px 宽度下必须换行而不是溢出。

## 组件边界

页面拆分为以下职责清晰的组件：

- `ApplicationShell`：导航、页面壳层和响应式布局。
- `TaskHeader`：任务标题、域名和安全操作。
- `TaskStageStepper`：四阶段显示和当前阶段摘要。
- `LiveBrowserStatus`：浏览器连接、用户活动和页面稳定状态。
- `TaskAttentionList`：风险项排序、计数和选择状态。
- `TaskAttentionDetail`：单个风险项的证据、映射和用户操作。
- `CompactActivityFeed`：最近活动及展开后的完整事件流。

组件只通过已定义的任务、进度和事件类型通信，不直接访问 API 内部状态，也不持有提交能力。

## 错误与恢复

- 网络或事件流断开时保留最后一个已知状态，并显示“等待重连”，不把任务误报为完成。
- 当前操作超时时显示操作名称、重试条件和恢复按钮；重试继续服从后端操作策略。
- 用户活动导致自动填写暂停时，显示暂停原因和“页面稳定后继续”入口。
- 任务处于 `review_locked` 时，界面隐藏所有自动执行按钮，只保留查看、取消和用户自行操作浏览器的提示。
- 删除任务等破坏性操作使用明确确认，不与提交动作混淆。

## 测试与验收

前端测试覆盖：

- 四阶段在所有后端状态下显示正确。
- 当前操作、风险计数和最近浏览器活动实时更新。
- 追问、自我评价审核、断线和审核锁定状态显示正确。
- 审核锁定状态没有提交或确认申请按钮。
- 320px、768px 和桌面宽度下无横向溢出、文本遮挡或布局跳动。
- 旧任务 API 响应缺少新进度字段时仍能显示基本状态。

验收以 Playwright 截图和组件测试为准；不要求真实招聘网站提交，且所有测试必须验证提交计数为零。

## 明确不做

- 不增加自动提交按钮或隐藏提交路径。
- 不在任务主视图中展示营销文案、装饰性插画或无关统计图表。
- 不把完整浏览器 DOM、向量内容或敏感档案值直接渲染到活动日志。
- 不为视觉重做引入新的状态机或第二套任务数据源。
