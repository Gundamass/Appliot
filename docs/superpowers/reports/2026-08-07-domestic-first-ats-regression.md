## DJI 重点检查

- 页面包含推荐码、简历与照片两个上传入口，简历上传语义可与照片上传区分。

- 学校、专业等搜索型自定义下拉执行“输入候选值、等待选项、精确选择、回读”。
- 登录浮层存在时，底层表单不会抢先进入填写流程。
- 复用已登录会话时，真实任务完成 40 个字段的填写或已有值回读，并安全停在补充问题阶段。
- 页面底部 `预览并提交` 被归类为终局操作，自动化权限层不允许点击。

## 本轮发现与修正

### 超长原生下拉选项截断

真实 Lever 院校字段包含上千个原生 `option`。浏览器观察为控制快照限制体积，只保留前一部分并标记 `optionsTruncated`。此前 RAG 会把这部分误当成完整选项集，导致排在后面的真实学校无法通过验证。

修正后，已截断的原生下拉采用档案精确值解析，不向 RAG 声称局部选项是完整集合；执行器仍通过浏览器原生 `selectOption({ label })` 在真实 DOM 中精确选择并回读。目标不存在时执行失败并交给审核，不做近似替换。

### 旧构建产物

主端口 `43120` 曾运行旧 `dist`，真实任务创建返回 `application_task_creation_failed`；同一请求在当前源码的隔离 API 上可正常进入 `waiting_for_login`。本轮已重新构建并重启主服务，随后在 `43120` 完成真实 DJI 填写回归。

## 真实回归剩余问题

- 招聘信息来源、是否接受意向城市调剂、当前所在国家和实验室经历等资料在当前候选人档案中没有已确认答案，按安全策略进入集中追问。
- 赛事信息、附件链接、补充说明及部分重复经历的通用年月字段仍缺少稳定语义，后续应继续增强重复区块索引和国内 ATS 字段目录。
- 未登录的新环境仍必须由用户完成登录、验证码或扫码；身份认证边界不由自动化代办。
